## ε 按证型分层：为什么不能拿一个全局 ε 当阈值

**这是这一组数里最容易被写坏的地方**，所以这一节的每个数都从
`eval/epsilon.json` 的 `per_query` 机读（`python -m scripts.collect_results`
的「ε 分层」一段），不是「大概从 0 到 0.5」这种描述。

同一个系统、同一条主诉、同一位医家，连跑 3 次，两两比较用药集合的 Jaccard 距离，
取均值 = **这条主诉的噪声地板**。9 条可用主诉（第 10 条解黑便，被安全否决跳过）
的地板是：

| 主诉（前 22 字） | 这条的地板 | 该条最小 | 该条最大 |
|---|---|---|---|
| 胸脘痞闷，呕吐清水痰涎，头晕目眩，心下悸动… | **0.0** | 0.0 | 0.0 |
| 脘腹胀满疼痛，嗳腐吞酸，恶闻食臭，呕吐不消化… | **0.0** | 0.0 | 0.0 |
| 心下痞满，按之不痛，干噫食臭，肠鸣下利，兼见… | 0.0556 | 0.0 | 0.125 |
| 胃脘灼痛，饥不欲食，口燥咽干，大便干结，形体… | 0.2 | 0.0 | 0.9 |
| 胃中隐痛，喜温喜按，空腹尤甚，得食稍缓，神疲… | 0.2146 | 0.0 | 0.9 |
| 脘腹痞满，口苦口黏，纳呆恶心，身重困倦，小便… | 0.3212 | 0.0 | 0.8571 |
| 食少腹胀，食后尤甚，大便溏薄，稍进油腻则次数… | 0.3969 | 0.0 | 0.8333 |
| 胃脘刺痛，痛处固定不移，拒按，入夜尤甚，病已… | 0.4704 | 0.0 | 0.8 |
| 胃脘胀痛，食后加重，嗳气泛酸，每因情志不畅而… | **0.5099** | 0.2222 | 0.6923 |

**全局均值 0.241。逐条地板 0.0 ~ 0.5099，最高的一条是全局均值的 2.12 倍。**
两条主诉的地板恰好是 0（同一条主诉跑三次，用药集合逐字相同）。

拿 0.241 当唯一阈值会**同时犯两个方向的错**，条数是算出来的，不是估的：

- **5 条**主诉的地板**低于** 0.241。这些条上，真实分歧只要落在「它自己的地板 ~ 0.241」
  之间，就会被当成噪声**漏判**。最极端的是那两条地板为 0 的：它们跑三次一模一样，
  任何差异都是真的，而全局阈值会把 0.241 以下的差异全部吃掉。
- **4 条**主诉的地板**高于** 0.241。这些条上，噪声只要落在「0.241 ~ 它自己的地板」
  之间，就会被当成真实分歧**误判**。最极端的是 0.5099 那条：它自己抖动就能到 0.51，
  用 0.241 判，一半的噪声会被报成「两位名医意见不同」。

两个方向分开报，**不合成一个「错判率」**——漏判和误判在这个项目里的代价不一样：
漏判是少说了一句话，误判是把系统的抖动包装成学术发现。

所以 `eval/run_eval.py::divergence_per_query_detail` 是**逐条配对**比较的
（每条主诉 × 每位医家各自跟自己的地板比），第 2 行那个「6/9 条超出」就是这么数出来的。
`offline/estimate_epsilon.py` 也因此必须逐条输出 `per_query`，不能只给一个均值。

**按医家也有分层**（同一份文件里读的）：ye_tianshi 0.2009 / wu_jutong 0.1972 /
zhang_xichun 0.3247。张锡纯那一支的地板明显高——他的医案里西药和中药混用，
用药集合本身更不稳定。所以配对也要带上医家，不只带主诉。

## 每组的 caveat（不是脚注，是数字的一部分）

1. **ε 按证型分层**：见上一节。#2 的判定是逐条配对做的；拿全局 mean 0.241 一刀切
   会在 5 条上漏判、4 条上误判。
2. **E3/E4 的「修复前」数**（0.335 / 0.351）成立的前提是「只改了检索层」——模型和
   主诉都没换。这两个数在本仓库里有文件凭据（见上面那一节），当前值没有。
3. **E8 的 graph 模式覆盖率 caveat**（原样从 `report_e8.json` 带出来）：graph 模式依赖
   `data/element_index.json` 把医案连到证素，覆盖率不是 100%，**这台机器上实测
   444/941（47%）**。覆盖不到的医案在 graph 模式下证素集合为空、相似度恒 0，系统性排在
   检索结果之后。所以 graph 模式如果差异更大/命中更低，**优先怀疑覆盖率而不是图检索
   方法本身**——不要据此断言「知识图谱检索不如向量检索」。
4. **SDT 的 27.729 是关掉安全否决之后的分**，差 4.90 分是安全否决的代价、不是缺陷：
   被拦的 **10/50** 条全部真危重（用官方 `Test_TCM_Data_v1.json` 过现在的
   `core.safety.check_safety` 现算确认；SOURCES.md 第 14 条原来写的 8/50 是词表扩充前的
   旧估算，已作废）。台账里那条 `partial: true` 指的是只用 `--only-ids` 重跑了被拦的
   记录再并回主提交文件，分数仍是完整 50 条的分。
5. **官方 Validation 金标准开头有 UTF-8 BOM**，`evaluate.py` 用默认方式读，BOM 粘在第一条
   病案 ID 上，那一条恒 0 分。**保留这个行为**（论文里 15 个模型大概率也是这么跑的，
   「修好」反而不可比）。实测代价：满分提交在 Validation 上只能拿 **48.9998/50**。
   上表第 7 行是 Test（Test 没有 BOM），不受这一条影响。
6. **E9 = 0.463 和修复前的 0.250 测的不是同一个东西**：那次测量里 ReAct 被引导去查医案层
   （SOURCES.md 第 30 条的成果），但 physician 参数填的是中文名、医案库按 id 存，
   9 次调用全空，模型只能退回国标层（第 31 条）。修复后的 E9 是另一个实验，
   0.250 只能当「修复前」读，不能当「ReAct 本来就没用」读。
7. **#9 的汇总均值方向对、逐条只成立 5/9**，所以它只报出不设闸门。三方两两配对
   （`school_pairs`）而不是算一个三方交并比：三方交并比在师承内和跨学派之间分不出来
   （总纲 1.3 / E2）。
8. **#10/#11 是沙盒模拟，跟 #1 不是同一个口径**：那组数只有一条主诉、一位医家
   （诊断报告里重复三次的那条），单条整方 ε 是 0.5769——它是最坏的一条，跟 #1 的
   9 条主诉汇总 0.241 不能混着引。role 也是我手工按君臣骨架标的，不是模型标的，
   所以那组数证明的只是「分层的算法真的把核心判断和加减分开了」
   （0.0 < 0.5769 < 0.8426），不是「真机上 ε_core 会是 0」。
9. **MES 是唯一不依赖自动指标的证据**，也是训练（阶段五）的靶子——三个前提
   （E3 ≥ 40% ✅、SDT 有基线 ✅、MES 显示哪个维度弱 ⏳）现在满足两个，所以 R5 只准备了
   训练代码和数据，没有训练。
10. **模型不同数字不可比**：上表全部是 DeepSeek 后端（「后端」列写明了，未做/沙盒模拟的行
    没有冒充成 DeepSeek 跑的）。将来训练后的本地模型重跑这整张表，按下面
    「同一指标、两个后端」那一节**并列**加行，不覆盖，并带上

## 同一指标、两个后端：并列，不覆盖（R5-4）

阶段五训完 LoRA 之后，同一个指标会有两个值：DeepSeek 跑的和本地模型跑的。
**规矩是加行，不是改行。**

上面那张表的「后端」列就是为这件事加的。本地模型的数按同样格式追加成新行，
编号沿用原指标号加后缀（`3-local`、`5-local`），原行一个字不动：

| # | 指标 | 后端 | 当前值 | 对照 | 闸门 | 状态 | 凭据 |
|---|---|---|---|---|---|---|---|
| 3 | E3 own vs swapped | deepseek-chat | 0.451 | 修复前 0.335 | ≥ 0.4 | ✅ AutoDL 实测 | 见上表 |
| 3-local | E3 own vs swapped | tcm-local（Qwen2.5-1.5B + LoRA） | 待跑 | **同一行的 deepseek-chat 值 0.451** | ≥ 0.4 | 待训练 | 待跑 |

为什么不能覆盖：

1. **覆盖掉的那个数就是这个新数唯一的对照。** 项目纪律是「任何数字都必须带对照」
   ——训练后的 E3 拿什么比？只能跟训练前同一批主诉、同一套代码、另一个模型的
   0.451 比。把 0.451 改掉，新的 0.451→0.4x 就成了一个没有基准的数。
2. **两个数不是同一次测量的修正，是两次不同的实验。** 覆盖适用于「上次算错了」，
   这里是「换了模型重测一次」——两者都是真值。
3. **本地模型一定会有几项更差。** 1.5B 打不过 DeepSeek 是预期，不是失败；
   并列摆着才能说清「差多少换来了什么」（自部署、零 API 成本、可按医家定制）。
   只留一份数就只能在「报一个更差的数」和「不报」之间选，两个都是错的。

怎么保证每个数都带后端标签：

- `eval/run_eval.py` 的报告里第一项就是 `backend`（`backend_tags()` 从每条结果
  自带的 `manifest` 抬上来，不读 `LLM_MODEL` 环境变量——那个变量在 claude_cli /
  replay 后端下还是 `deepseek-chat`）。`report.md` 顶部有一行 `**后端**：…`。
  **一份报告里混了两个后端会在那一行大声报出来**（`mixed: true`）：混着跑出来的
  每个汇总数字都是跨模型的平均，谁都比不了。
- `eval/sdt/run.py` 的提交元数据里有 `backend`（R2 就有了）；
  `offline/estimate_epsilon.py` 写的 `eval/epsilon.json` 里有 `model` / `backend` /
  `comparability_warning`。
- 回放（`LLM_MODE=replay`）跑出来的数，`replayed_from` 非 None，报告顶部会写明
  **不是实时调用**。回放的数字跟实时的数字长得一模一样，不标就等于伪装。
- 盲评的 `answer_key.json` 里有保留键 `_backend`，`eval/mes/collect.py` 把它写进结果；
  老答案表没有这一项时明确写「来源不明」，不猜一个默认值。
- `scripts/train_lora.py` 最后打的那张 train/heldout loss 对照表**不是**这张表的
  行：loss 不是靶子，它只回答「哪个基座在 heldout 上更低」。训完要按上面的口径
  重跑 ε/E3/E4/E8/E9/SDT/MES，才有资格往这张表里加行。
