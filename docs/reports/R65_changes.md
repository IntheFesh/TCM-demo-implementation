# R65 变更说明：验证否决的呈现

**1. 医师不整页拦截。** 医师/学生照常拿到完整推导与全部药味，出问题那味标红、
原因在旁，顶部一条黄条（不是整页红），导出禁用并说明原因。患者仍不给方，措辞
改为「本次未能给出可供参考的方剂」。

**2. 规则名全转人话。** 新增 `core/veto_text.py`，十三条规则全覆盖，规则 id 只
进 `detail`、只给内部角色。之前过滤不住是因为文案有**两处**拼装：
`SymbolicVeto.reason` 也在拼，且经 `agent_trace` 发给所有角色——那才是漏点。
「请尽快就医」「本页不提供方药内容」收归红旗专用，加源码级测试。

**3. 第 4 项：不是配置差异**（产品与 R57 消融逐项相同）。根因是
`herb_source_fabricated` 的归属判据：双向子串一命中就算"找到主人"，而本草原文
多是格式化短语、本体还有 1~2 字 span。拿本体自己的真实原文去问归属：

| 同种子同样本 200 条 | 修前 | 修后 |
|---|---|---|
| 真实原文被指认给别的药 | 146/200 = 73.0% | 15/200 = 7.5% |

修法：重合段 ≥6 字且主人唯一才算指认得出，判不准退 revise 而非 veto。残余是语料
自身重复。复现 `python -m scripts.diagnose_veto_attribution`。**真机才能确认**：
沙盒无真实模型，三条主诉是否还 veto 取决于模型引文写法，上表是误判率而非承诺。

**4. 验证。** `pytest -q` 全绿（新增 55 条）、`ruff check .` 干净、Playwright 跑过
否决那一屏。`grep -c "= Field(min_length=1" core/schemas.py` = **117 处**，本轮未
动此文件；CLAUDE.md 记的 72 是 `931cdc7` 的数，R62~R64 涨到 117 全是新增（逐行
比对旧版无一行消失）。
