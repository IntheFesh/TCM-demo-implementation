## 三、Playwright 抓到的四件事（这一节是本轮报告的重点）

CLAUDE.md 那条硬约定写的是「涉及图层结构变更时，Playwright 是必需的验收环节」。
这一轮它兑现了四次，**两次是判据红、两次是看图看出来的**——后两种自动判据抓不到。

### 3.1 判据红（纯函数测试全绿）

**① 对照带换成 SVG 之后，旧判据查的元素已经不存在。**
`screenshot_states` 里那条 `done` 判据查 `#rx-compare .rx-seg`（两个 div 段）。
改成 SVG 之后结构没了，判据当场红——而 `tests/` 里的 node 测试全绿，
因为它们查的是**新函数的输出**。判据跟着结构改，但问的还是同一件事
（两段在不在、噪声段是不是更长），另加两条 R24 特有的：带高 ≥ 12px、
斜纹 `pattern` 在不在——**只查"有两个 rect"的话，把 fill 换回第二种灰也会绿**。

**② token 面板嵌在折叠区里，`innerText` 读回空串。**
面板挂在 manifest 旁边，而那块在「图谱与细节」这个 `<details>` 里。
`innerText` 只返回**渲染出来的**文字。这一条本身就是"在 DOM 里"和"看得见"
两件事的区别——而这个项目的安全边界判据（患者响应体里搜不到药名）正是建立在
两者不同上。判据改成把祖先的 `<details>` 一路打开再读。

### 3.2 看图看出来的（DOM 断言两种写法都能过）

**③ 建议行把药名渲染了两遍。**
截图里是：「甘草、甘遂 甘草 与 甘遂 属配伍禁忌，同方相见须改方 十八反」。
`check_formula` 五条规则的 reason **都已经点名了涉及的药**，前面那个 herbs span
是纯重复，读起来像数据出错了。改成只进 `data-herbs` 属性（给机器读）。
**DOM 断言查的是"药名在不在"，两种写法都能过。**

**④ 方剂评分 `0` 和 `0.7` 并排不等宽。**
`String(0)` 出来是「0」。三列对照页里这种不齐会被读成别的意思。固定两位小数。

**⑤（同类）题记初稿写了「两位名医」**，而注册表现在跑三位。
这是 CLAUDE.md「写死的常量也算一处实现」在文案上的形态——它就在首屏正中央，
而加一位医家时没有任何东西会提醒你改它。改成不写数。

## 四、每项改动的验证方式与结果

**1 自绘下拉。** 三条判据钉住"原生元素仍是值的唯一来源"：代码里不出现
`remove`/`replaceWith`、写值之后要 `dispatchEvent(change)`、隐藏用 `opacity` 而不是
`display:none`（后者让 Playwright 判定元素不可交互）。键盘契约抽成纯函数
`selectKeyAction(key, isOpen)`，十个键逐个断言——自绘之后原生白送的那一半必须
自己实现，而键盘是最容易漏的那一半。真浏览器那一层单独验：`r24_select_open`
用 `KeyboardEvent` 打开、移动、回车，断言值真的写回了原生 `select`。

**2 题记。** 判据除了三行结构，还有一条**"不许出现引文式表述"**
（`云：` / `曰：` / `《…》云`）和一条**"不许出现医家数"**。
两条都是"防止编造"的判据，不是排版判据。

**3 字体子集化。** 字表 1817 个字符，来源是 `web/*` + `core/physicians.py` +
`core/elements.py` + `core/diseases.py` + `api/main.py` + `data/standard/syndromes.jsonl`。
判据：确定性（两次收集同一个集合）、不含控制字符、`U+XXXX` 形状、
四个字面跟 `@font-face` 数目一致、**脚本不自动改 app.css**。

**4 对照带。** 见 3.1 ①。

**5 四级层次。** CSS 判据逐级查"用的是不是不同手段"：证型 17px、治法
`var(--font-ui)`（换字族）、方名 `border-top`（加界线）、药味 `grid-template-columns`
（两列）。Playwright 那一层加了一条**药味左边界必须对齐**
（`herbCells` 的 `left` 只有一个值）——那是两列排版的全部意义。

**6 去卡片化。** 逐块查 `border-radius` 不在、`border: 0` 在；**另有一条反向判据**
查按钮/chip/自绘下拉的圆角还在——去卡片化针对的是常驻内容块，不是控件。
一个例外写明了理由：医生模式免责条保留紫底（它是法律声明）。

**7 两环。** 半径是**量出来的**：内 649 / 外 1972 / 比值 **0.329**（20 枢纽 + 61 节点）。
判据因此从 R16 那条 `> 0.15` 收紧到 `> 0.25`，卡在实测值下面一点点。
另加一条"外圈是一簇不是好几圈"（相对标准差 ≤ 0.35）。

**8 顶栏 / 建议 / token。** 顶栏默认展开且 `localStorage` 读不到时按默认走
（隐私模式下 `getItem` 会抛）；建议三档颜色在真浏览器里用 `getComputedStyle`
断言**三个值互不相同**；"没跑的规则"不许被折叠（`closest('details')` 为 null）；
token 面板必须同时有"本次"和"今日累计"两段，且千分位（`180,412`）——
那个数是要跟 500,000 预算对着看的。

## 七、发现但未动 / 发现并当场修了

**1. 新加的 CSS 差点用了三个不存在的令牌（已修）。**
初稿写了 `var(--fs-small)` / `var(--fs-tiny)` / `var(--sp-2)`——这个项目的字号是
字面 px、间距是 `--s1..--s8`。**不存在的 `var()` 不会报错，浏览器只是丢掉那条
声明**，于是字号静默继承。抓到它的是"写完回头对一遍 `:root` 有哪些令牌"，
不是任何自动判据。值得单独记：CSS 里不存在的变量是这门语言里最安静的一类错误。

**2. `bench_sandbox` 里写死的「16 种状态」（已修）。**
那行进度文字是写死的，R24 加到 20 种之后它仍然打印 16。改成
`len(STATES)` 现算——**写死的常量也算一处实现**，而这一处的错误形态是
"报告里两个数对不上，但两个都不报错"。

**3. 留着没动：`candidates_scored` 没有渲染。**
R22 产出了"这次采了 N 张、每张多少分、选了哪张"，R24 没有把它画出来。
不做的理由是**它需要一个新的展示形态**（三张方的对照，而现在整页的对照轴是
"三位医家"），硬塞进现有的列里会变成第四层折叠。它属于"有数据、还没有位置"，
记在这里等一个真正需要它的场景，而不是先画一个没人看的表。

**4. 留着没动：图谱浏览器的缩放。** 两环在模型坐标里是 1:3，但整图 fit 之后
内圈只有约 80px——61 个外圈节点加标签把画布撑开了。真正的解法是"点一个枢纽
就只看它那一簇"（局部视图），那是一个交互设计问题，不是一行 `minZoom`。
现在如实记着：**两环的结构是对的，可读性在节点多时会掉**。
