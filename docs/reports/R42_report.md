## 1. 九层：为什么是九层，缺层怎么办

### 1.1 原来那张图回答不了"为什么"

改之前 `到证型` 这一步把「脏腑」和「病性」挤在一个「证素」层里，「病机」根本没有
位置，「治法」挂在 证型→方剂 那条边的 `label` 上。那张图看得出"从症状到方"，
**看不出为什么是这个证、为什么是这个治法**——而那正是辨证这件事本身。

九层与 `S3Structured` 的九段一一对应：

```
症状(0) → 脏腑(1) → 病性(2) → 证型(3) → 病机(4) → 治则(5) → 治法靶位(6) → 方剂(7) → 君臣佐使(8)
```

第 6 层叫**治法靶位**而不是「治法」：它的内容是 `MethodStep.targets`，schema 里
写明那是"这个治法分别针对哪几条病机"——是靶位（肝、胃…），不是治法本身（治法在
第 5 层的 `principle` 里）。叫「治法」会让图上出现一个写着「肝」的治法节点。

### 1.2 缺层如实报，不伪造

legacy `S3Syndrome` 没有病机和治法靶位。**那两层就是空的**，链条直接从证型接到
治则、从治则接到方剂，层号进 `missing_layers`，前端的层名列头照样出那两格并标成
「本次没有」（朱砂虚线，不是灰掉——灰掉读起来像"这一层不重要"）。

从 `reasoning` 里切一句话当病机是伪造：那段文字是模型的自由叙述，不是它标定的病机。

实测（三位医家、legacy S3）：`missing_layers == [4, 6]`，层名列头 9 格、其中 2 格
标「本次没有」。

### 1.3 **本轮发现的一个真 bug：病机/治法在生产里永远是空的**

写完九层之后 Playwright 的 `single_chain_graph` 第一次跑就红了：

```
第 4 层一个节点都没画出来：{"0":3,"1":2,"2":1,"3":1,"5":1,"7":1,"8":4}
```

根因：`consult()` 给下游的 `results[i]["s3"]` 是 `to_s3_syndrome()` **扁平化之后**
的那一份，那次转换把 `organs[]`（病机）与 `method.targets`（治法靶位）丢掉了，
只留下 `treatment_principle` 一个字符串。原件在 `results[i]["s3_structured"]` 里。

只读 `s3` 的话，这两层在**生产里永远**是空的——而 `missing_layers` 会如实把它们
报成"本次没有"，看起来像"这一轮的模型没产出病机"。**后端的 JSON 结构测试全绿**
（喂的 fixture 本来就是 legacy S3），只有把真 payload 喂进浏览器才看得见。

修法：`to_graph` 里 `st = r.get("s3_structured") or s3`，病机/治则/治法从 `st` 读，
其余从 `s3` 读。修完实测 `missing_layers == []`，九层齐。

**这正是 CLAUDE.md 那条硬约定的第二个实例**（第一个是 M5 的 `nodesByLayer`）。

### 1.4 前端一个层号清单都不写

M5 的教训原文：`to_graph()` 的 Python 单测全绿，前端 `growGraph()` 的
`nodesByLayer` 初始化漏了新加的 layer 4 这个 key。R42 把层数从 5 改成 9，同一个
坑会再踩一次——所以这一轮的做法是**层序全从后端下发的 `graph.layers` 取**，
前端不写任何层号清单：

- `nodesByLayer` 从 `Map` 现建，键来自数据；
- 入场间隔表 `LAYER_STAGGER` 查不到就用默认值（`LAYER_STAGGER_DEFAULT`）；
- 层号缺失/越界归到 `-1`，先画、不崩；
- compound 父先于子：**升序遍历层号就满足**（方剂 7 < 君臣佐使 8），没有另写特例。

判据：`tests/test_graph_nine_layers.py` 里那四条源码判据（正则查禁止出现的形状，
**只看代码行、不看注释**——注释里必须能提到那个形状，那正是在解释为什么不该这么写）。

## 2. 布局：dagre，以及为它踩的两个坑

### 2.1 为什么换掉手写布局

手写布局**不知道标签有多宽**：横向由 `LAYER_X` 写死，纵向由 `evenY` 等距分，
而一个五个字的证型名比一个两个字的证素宽一倍多。R24 因此加了一串"标签上限"常量
去**压字**，R37 又实测出 `text-max-width` 断不了中文（只在空白/换行处断行）——
那串常量既压不动最宽的标签、又让别的标签白挨一刀。

dagre 反过来：**把每个节点的真实盒子尺寸告诉布局算法**。重叠因此是结构上不可能。
R24 那串压字常量（`LAYER_X` / `Y_MIN` / `Y_MAX` / `HERB_GAP` / `evenY`）随之退役，
`labelMaxFor` 只留一个很宽的上限当兜底。

用**裸 dagre** 而不是 `cytoscape-dagre`：后者要在 cy 实例上跑，那就进不了 Worker；
裸 dagre 是纯函数式的，R41 建的那条 Worker 通路一行没改。

### 2.2 坑一：dagre 0.8.5 不能处理"边的端点是 compound 父节点"

方剂节点同时是两件事——compound 父（里面装着君臣佐使），又是 治则/治法→方剂 那条边
的终点。两件事同时交给 dagre，它在 `nestingGraph` 那一步抛：

```
TypeError: Cannot set properties of undefined (setting 'rank')
```

隔离出来的最小复现（`dagre.version === "0.8.5"`）：

| 构造 | 结果 |
|---|---|
| `setNode(p/f/h)` + `setParent(h,f)` + `setEdge(p,f)` | **抛** |
| 同样三个节点，边改成 `setEdge(p,h)` | 正常 |
| 有 parent、完全没有边 | 正常 |
| 有边、没有 parent | 正常 |

而 `computeLayout` 的 `try/catch` 会**静默**退到 `fallbackLayout`——图还画得出来，
只是等距铺开、可能重叠，没有任何报错。

修法：**把 compound 整块当一个盒子交给 dagre**——子节点不进 dagre，父节点的尺寸按
"能装下它全部子节点"算，dagre 算完子节点在那个盒子里竖排。cytoscape 本来就是按
子节点算父节点包围盒的（所以父节点不给坐标），两边正好对上。

顺带把那条 `catch` 改成**留痕**：`_computeFallbackReason` 记原因，`layoutStats`
把它和 Worker 那一层的原因**一起**报（两层回落各自独立，二选一的写法会让"图为什么
重叠"查不到）。

### 2.3 坑二：dagre 按最长路径排 rank，不认我们的 layer

实测（R37 那份真 payload）：病性(2) 与脏腑(1) 都只有"症状→它"这一条入边，于是
**同 rank、挤在同一列**（x 都是 403）；症状(0) 自己还分裂成两列（119 / 260）。
而九层图的全部意义就是"第几层 = 第几列"。

试过并否掉的做法：加隐藏根、向每个节点连 `minlen = layer + 1` 的边。
`weight: 0` 时 network-simplex 根本不去拉紧它们（权重为 0 的边对目标函数没有贡献），
层号照样对不上；把权重调上去又会让这个"连到所有节点"的根参与排序阶段，搅乱纵向次序。

最终分工：**横向（第几列）我们自己定，纵向（同列里的次序）交给 dagre**——后者才是
难的那一半（交叉最小化），前者是一条我们本来就知道答案的规则。同层内再做一次
"保序拉开间距"，因为 dagre 只保证同一个 rank 内不重叠，而我们的一层可能被它拆到
两个 rank 上。

实测九列的 x（R37 单链）：`62 / 198 / 322 / 504 / 725 / 939 / 1106 / —— / 1278`
（第 7 层是 compound 父，不给坐标）。

### 2.4 零重叠 / 零穿越：实测

| 图 | 节点 | 边 | 重叠对数 | 交叉数 | 数据逼出来的下界 | 超出 |
|---|---|---|---|---|---|---|
| 三医家九层图 | 23 | 22 | **0** | 6 | **6** | **0** |
| 单链九层图（R37 真 payload） | 17 | 14 | **0** | **0** | 0 | **0** |

**那 6 对交叉不是布局的错，这句话必须跟着数字走。** 证素层是全局共享的那一份，
三位医家给出三个不同证型 → 证素→证型是全连接；两列之间只要出现一个 K₂,₂
（两个上游各自都连到同样的两个下游），那一对边在**任何**两列直线画法下都必然交叉
——换排序只是换哪两条交叉。脏腑 2×3 给出 C(2,2)·C(3,2)=3 对，病性同理 3 对，
合计 6。量出来正好 6，**布局一对都没多加**。

所以判据是 `excess == 0`（多结论并列）与 `n_crossings == 0`（单链，此时下界必为 0），
不是一句笼统的"零交叉"。

### 2.5 布局耗时

| 场景 | 规模 | dagre | 兜底（等距铺开） | 说明 |
|---|---|---|---|---|
| 单链九层 | 17 节点 / 14 边 | **4.2 ms** | 0 ms | 主线程中位数，21 次 |
| 图谱浏览器聚焦（`element::肝` 一跳邻域） | 15 节点 / 14 边 | **3.4 ms** | 同心环 0 ms | `__gbPerf.benchLayouts`，7 次中位数 |
| 端到端（含 Worker 往返、建线程） | 23 节点 | 66.1 ms | — | `layoutStats.ms`，`where: "worker"` |

**诚实的负面结论**：在当前规模上 dagre 比同心环慢（3.4 ms vs 0 ms），Worker 往返
（66.1 ms）远大于布局本身。换 dagre 的理由从来不是"更快"，是**结构上不重叠**；
Worker 的理由也不是现在快，是 R41 写明的"图会长大"。这两条都没有变成"性能优化"，
报告里不许把它们写成性能收益。

## 3. 去医家分带：合并，但不丢"谁给的"

id 里不再有 physician 段（`syn::{证型名}` / `formula::{方名}` /
`herb::{方名}::{药名}`）。同名节点合并成一个，贡献者记在 `contributors`。

**"这一步是谁给的"不能因此丢掉**（能力不删）：

- 只有一位贡献者 → 用那位医家的色**描边**（填充仍归层级族，层级不被打乱）；
- 多位贡献者 → **双线边框**，意思是"几位医家给出了同一个结论"。

两个标记（`contributor_solo` / `multi_contributor`）由后端在建完图之后统一算——
cytoscape 的选择器选不了"数组长度 > 1"，前端按 `contributors.length` 现判就是
同一个判断的第二处实现。

并列不等于分带：给出不同证型时是几个证型节点并列在同一列上，上游连回同一批证素。

## 4. 视觉层级：四族一焦点，一个新色相都没加

总纲 §2.1 定的规矩是「带颜色 = 属于某位医家，或者在报警」。九层各给一个色相就是
一道彩虹，正好是 §1 第一条要避开的通用模板相。所以九层按**读图的四段**分族：

| 族 | 层 | 底色令牌 |
|---|---|---|
| 输入（最轻） | 症状(0) | `--node-input-bg` |
| 辨证 | 脏腑(1)/病性(2)/病机(4) | `--node-reason-bg` |
| 焦点（最重，字号+字重+2px 边框） | 证型(3) | `--node-focal-bg` |
| 治疗 | 治则(5)/治法靶位(6) | `--node-treat-bg` |
| 方药 | 方剂(7)/君臣佐使(8) | `--node-rx-bg` |

五对令牌全部取自同一族草木灰，只有深浅差别。层级的主要载体是**字号**
（`LAYER_FONT_SIZE`，样式表与 dagre 留位读同一个函数——两处不一致就等于"按一个
尺寸留位、按另一个尺寸画"）。

## 5. 节点释义：四节 → 八节

| # | 节 | 回答 | 数据来源 |
|---|---|---|---|
| 1 | 是什么 | 身份/定义 | 证候表 / 本草本体 / 方剂本体 / 证素词表 |
| 2 | **病机** | 它在病机链的哪一步 | 证候表的 location/nature 两列；病机节点自身 |
| 3 | **药理** | 结构化属性值，**缺哪个谓词如实列出** | 药理层三元组 |
| 4 | 出处原文 | 上面那些值各自出自哪一句 | `source_span` + `book` |
| 5 | 名老中医经验（原「名医怎么用」） | 五家在医案里怎么用它 | R35 `prescribing_patterns.jsonl` |
| 6 | **验证结果** | 七条规则里哪几条**能**对它求值 | `core/formula_verifier.RULE_LABELS` |
| 7 | **循证对照** | 依据落在哪几部书、对照基准是什么 | `Ontology.source_books()` / 证候表 `source` |
| 8 | 注意 | 剂量上限 / 十八反 / 炮制 | `core.safety_output` |

四条纪律（零 LLM / 取不到就说取不到 / 判据全部复用 / 任何数字都必须带对照）在
模块文档里逐条写明，判据在 `tests/test_node_explain_sections.py`（35 条）。

几个容易犯的错，各有一条判据钉着：

- **病机**不许从 definition 里切一句话——证候表没有独立的病机字段，这一节报的是
  病位+病性两列并把这件事说出来；病机节点**只做要素级匹配**，不拿整句去子串比。
- **药理**必须列出缺的谓词，并带全库同类缺口（"这一味缺归经"和"全库 1319/1458 味
  都有归经"是两回事）。
- **名老中医经验**空着时要说"查过了、规律层 1924 条里没有一条提到它"，
  而不是让那一节整块消失——**空着跟"这一节我们没做"在界面上长得一模一样**。
- **验证结果**报的是**可验证性**，不是本次处方的结论：结论是对一整张方求值出来的，
  这个接口只有一个节点 id，在这里现算就得拼一个假 S3——那是第二处实现。
  末尾指向问诊结果的「验证」段。
- **循证对照**永远带 `GUIDELINE_GAP_NOTE`：**《中医药循证临床实践指南》全文不在
  本项目内**（没有可用的授权文本），所以给不出循证等级；「教材里有这一条」不等于
  「有循证支持」。这一节列出的基准是仓库里真有的东西：

| 层 | 书 | 三元组 | 主体 |
|---|---|---|---|
| 本草 | 5 部（中药学 2563 / 中药炮制学 1390 / 临床中药学 1707 / 本草备要 3218 / 神农本草经 898） | 9776 | 1458 味 |
| 方剂 | 1 部（方剂学 3184） | 3184 | 235 首 |
| 证候表 | — | 337 条（textbook 320 / official_consensus 6 / secondary_verified 6 / journal 3 / group_standard 1 / manual 1） | 带 ICD-11 的只有 **1** 条 |

这些数字**全部从数据现算**，代码里一个都没写死（有一条测试用 AST 把文档字符串
排除掉之后检查所有会显示给人看的字符串——数法定死，跟 `Field(min_length=1)` 那条
同一个道理）。

**顺带修掉的一个真 bug**：`_PREFIX_KIND` 原来只认问诊图那一套前缀，持久图的
`element::` / `syndrome::` / `symptom::` 一个都不认——在图谱浏览器里点一个节点，
`parse_node_id` 判成 unknown、面板整块隐藏，而"隐藏"跟"这个节点没有释义"在界面上
一模一样。现在三张前缀表有测试互比（其中一条从 `data/graph.json` 的真 id 里现取，
不手抄）。

### 性能预算

八节比四节多读三张全量表（方剂本体、功效同义表、规律层）。预算 **p95 ≤ 50 ms**
（`api.main.NODE_EXPLAIN_BUDGET_MS`），**按热态量**（冷启动是本体惰性初始化的
一次性成本，跟这个接口的稳态延迟不是同一件事），判据进测试。

## 6. 交互：钉住 / 键盘 / 触屏 / 抽屉 / 导出

**tooltip 钉住**：hover tooltip 有三种人用不了——触屏没有 hover、只用键盘的人做不到
"鼠标划过去"、要**照着 tooltip 抄剂量进病历**的人手一移开就没了（三甲最常见的用法）。
点节点 = 钉住，钉住期间 hover 不再改动它，Esc 或点空白处取消。
两个状态的 `pointer-events` 诉求正好相反（hover 版必须 `none`，否则 tooltip 挡住
hit-test 会闪烁；钉住版必须 `auto`，否则选不中里面的字），这也是为什么钉住必须是
一个显式的 class。

**无障碍**：`role="status"` + `aria-live="polite"`（不是警报，不该打断读屏正在念的
句子）、画布 `tabindex="0"` + `aria-label`、`aria-hidden` 随显隐切换。

**窄屏抽屉（≤768px）**：释义有八节，窄屏上那张卡会把图整个推出屏幕——**点一个节点
看它的释义，结果那个节点看不见了**。抽屉从下面上来、≤60vh、关闭按钮 44×44（WCAG
最小触控目标）。768 是 iPad 竖屏宽度，也是三甲最常见的移动查房设备；640 那个断点
保留（它管"一栏还是三栏"，是另一件事）。

**导出 PNG**：`full: true`（整图，不是视口）、`scale: 2`（投影仪和打印要 2 倍）、
纸色底（默认透明底贴进深色文档会变成一片黑）、文件名带主诉与时间戳且不含冒号
（Windows 文件名非法字符）。

## 7. 图谱浏览器：聚焦 + 分层 + 面包屑

同心双环回答的是"这张图上都有什么"（概览）；真要看一个证型时问的是**"这一条是怎么
连起来的"**，而在环上那个问题答不了（相关节点散在不同角度，边跨过圆心交叉）。

双击一个节点 → 只看它的 k 跳邻域（默认 2 跳、上限 120 个节点，超了**截断并计数**），
**按跳距分层**，走的是问诊图**同一个 `computeLayout`**（一个算法只有一处实现）。
面包屑记这条聚焦路径，点任一格回到那一步；退出聚焦恢复的是**进聚焦前那批节点**，
不是重铺首屏（重铺会把用户展开了半天的那些丢掉）。

聚焦模式下环图例换成聚焦自己的说明（留着一句描述另一种布局的话比没有更糟），
并在 dagre 没加载上时**写在图旁边**——看图的人不开控制台。

**两种布局都留着，按测量选**：概览留环、聚焦用 dagre，因为两者回答的不是同一个
问题。实测（`element::肝` 一跳邻域，15 节点 14 边，7 次中位数）：同心环 0 ms、
dagre 3.4 ms——**dagre 更慢**，留它是因为它回答的是另一个问题，不是因为它更快。

## 8. 顺带修掉的三条既有缺陷

1. **`let cy` 声明在 app.js**，而只有 graph.js 在用。浏览器里两个 script 共享全局
   作用域所以从没报错，给 `exportGraphPng` 写只加载 graph.js 的 node 测试时第一次
   跑就 `ReferenceError: cy is not defined`。跟 R41 的 `LAYER_X` 同一个形状、同一个
   修法（搬到被依赖的那一侧）。**这是文件顶部那条"依赖方向只能 app → graph"的第二例。**
2. **`describeNodeTooltip` 的分派顺序反了**：它先判 `node_type`，而问诊图的节点
   从 R16 起也带 `node_type`——于是问诊图上 node_type 撞上持久图那几个值的节点
   全都走进了持久图那一支，表现是证型节点的 tooltip 里没有医家、方剂/药材层压根
   没有分支可走。现在按 `layer` 在不在分派（`layer` 是问诊图独有的）。
3. **`evt.originalEvent` 不保证存在**：cytoscape 的合成事件没有原生事件对象，
   裸读 `.clientX` 当场 TypeError，而它发生在 hover 处理里——表现是"鼠标划过图的
   时候整页的 JS 挂了"。六个调用点统一走一处 `eventXY()`。
