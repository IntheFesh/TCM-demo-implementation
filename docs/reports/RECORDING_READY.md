## 三、录制前必看

### 1. 起服务之前先跑一次自检

```bash
python -m scripts.preflight_deploy
```

退出码 `0` 全绿、`2` 有告警可起、`1` 有阻断项不可起。它会逐项告诉你缺什么
（数据文件、前端资产、端口、`LLM_API_KEY`、`EVAL_MODE` 有没有关掉）。

### 2. 三件"只有第一次才看得到"的东西——录之前先决定要不要拍

| 东西 | 只出现一次的原因 | 想拍到怎么办 | 不想拍到怎么办 |
|---|---|---|---|
| **三步引导对话框** | 看过就记进 localStorage | 用无痕窗口，或在控制台 `localStorage.clear()` 后刷新 | 先打开一次点掉，再开始录 |
| **预计剩余时间** | 要 3 次历时样本才给数，之前显示「样本不足」 | 先跑满 3 次问诊再录 | 照录，"样本不足"那句话本身是诚实的设计 |
| **知识速查的首次延迟** | 第一次 Ctrl+K 要装载本体，约 **2.4 秒** | —— | **录之前先按一次 Ctrl+K 查个词预热**，之后每次是 4 ms |

### 3. 角色决定看到什么——录制脚本里要说清现在是谁

产品模式下只有 **医师 / 学生 / 患者** 三档（在顶栏「设置」里）：

- **医师**：完整方药 + 个体化清单 + 循证对照 + **病历文书草稿**（只有这一档有）
- **学生**：方药与推导链有，没有病历文书
- **患者**：**没有方药、没有个体化、没有循证对照**——这是安全边界，
  不是功能裁剪（服务端就不下发这几个键）

要展示研究面（三列并列、分歧度、噪声地板、运行清单），用
`PRODUCT_MODE=0 uvicorn api.main:app` 单独起一次。

### 4. 几个交互的正确点法

| 要展示的 | 怎么点 |
|---|---|
| 结构化四诊录入 | 输入框**上方**的折叠行「结构化四诊录入（望闻问切 + 患者概况）」。点常用词会**追加**到字段里（不覆盖）。「从主诉框拆分」把已有主诉拆进表单，「填入主诉框」反向 |
| 个体化调整 | 要先在「患者概况」里填生理阶段（老年 / 妊娠期 / 儿童）或过敏史，**不填就没有这一块**（它会如实说"未填写患者信息"） |
| 循证对照 | 结果出来后在方剂区下方，**点那一行才展开**。展开后每条带《方剂学》原文 |
| 病历文书 | 切到医师模式后结果区自动生成，点折叠行展开。改任意一段 → 再点「复制病历文本」会把改动一起写进审计链 |
| 打印处方笺 | 病历文书里的「打印处方笺」→ 浏览器打印预览选 **A4 纵向**。预览里顶栏/图谱/输入区都不印 |
| 知识速查 | **Ctrl + K**（Mac 是 ⌘ + K），Esc 或点遮罩关闭。四类分开显示，右上角有本次耗时 |
| 九层推理图 | 展开「推理链 · 图谱 · 取证过程」。点节点**钉住**释义（八节），Esc 取消钉住；「⤓ 导出 PNG」是 2 倍白底整图 |
| 图谱浏览器 | 第二个页签。搜索后**双击**节点进入聚焦，上方面包屑可逐级退回 |
| 危重拦截 | 输入带「柏油样便」「呕血」之类的主诉，会**整页替换**成拦截页，不出任何方药——这是设计如此，画面上会很干净 |

### 5. 两个容易在镜头里穿帮的点

1. **页脚的「本次记录编号」每次问诊都会变**——它标识这一次问诊，不是版本号。
   如果要在画面上对照编号（比如展示按编号调阅病历），记得用同一次的那个。
2. **循证对照有 15% 的覆盖率**：换一条主诉很可能落在「未覆盖本证型」上。
   那一句话本身是诚实的设计（它还会说明"不代表推导有误"），但如果想拍到
   "主方一致 / 加减 N 处"的画面，建议先用几条主诉试一下再定录制用例。
