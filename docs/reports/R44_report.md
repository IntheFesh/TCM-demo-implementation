# R44：Agent 化（四能力 + 规则表驱动 + 消除投票痕迹）

> 这一轮**没有加任何新的判断**。它做的是两件事：把散在推理链里的九处 `if` 收成
> 一张**可读、可测、可改**的规则表；把结论顶上那句「五家综合」换成「本次辨证」。
> 前者让"系统在这一步做了什么、凭什么"第一次能被回答，后者让产品面从"几个人
> 投票"变成"一位医师引用了几家的经验"——**而融合能力一行没改**。

## 1. 为什么要这一层：三个具体后果

`consult()` 里对"停 / 问 / 取证 / 验"的判断原来长这样：

```python
if reject_reason is not None and not bypass:            # → 返回一份拦截结果
if followup.stopped_by == "safety" and not bypass:      # → 返回一份拦截结果
if reject is not None and not bypass:                   # → 返回一份拦截结果
except SafetyVeto:                                      # → 返回一份拦截结果
if not s2.elements and not residual…:                   # → 返回一份信息不足结果
except SymbolicVeto:                                    # → 返回一份拦截结果
```

**这不是风格问题，有三个具体后果：**

1. **那份"被拦截的返回值"有四份拷贝，而且已经开始漂**——其中一份带
   `"coverage": None`、另一份没有，键的顺序也各不相同。前端按同一份契约读，
   缺一个键就是 KeyError。
2. **"为什么停在这里"只存在于代码里**。返回值里只有一句 `reject_reason`
   （「检测到危重症状：吐血」），而三甲的主治医师问的是"系统在这一步做了什么
   决定、凭什么"——那个答案原来没有任何地方能给出。
3. **加一条新规则要改五个地方**，漏掉一处的表现是"某条路径上那个新判断没生效"
   ——正是 CLAUDE.md 第 31 条说的那种撞墙。

## 2. 四能力：不是四个新模块

| 能力 | 做什么 | **唯一实现**（`gate` 字段指着它） |
|---|---|---|
| `stop` 中止 | 停下来，不产出方药 | `core.safety:check_safety` / `core.formula_verifier:verify_formula` / `core.chain:infer_elements` |
| `ask` 追问 | 信息不够就问，不硬答 | `core.followup:run_followup` |
| `gather` 取证 | 缺依据就去查 | `core.react:run_react` |
| `verify` 自验 | 开完方自己验一遍，不合格就重开 | `core.formula_verifier:verify_formula` |

**"四能力"是给已经存在的四件事起了一个统一的名字**，好让"什么时候用哪一个"
能被写成一张表。`gate` 字段不是注释——有一条测试拿它去 `importlib` 核实那个符号
真的存在；另有一条扫描 `core/agent.py` 的函数体，**出现 `re.compile` / `DANGER` /
阈值常量就红**（那说明有人在这一层又实现了一遍判断）。

### 三条纪律

**一、顺序即优先级，安全永远在最前。** CLAUDE.md 的「安全否决在 S2 之前」与
「追问的回答必须先过 `check_safety`」两条铁律，在这张表里就是前四条的位置。
判据 `stop_rules_come_first()` 是可执行的，而且还要求四条安全规则**连续**
（中间插一条别的，就意味着有一条安全判断排到后面去了）。

**二、每条规则都要能说出"为什么"。** `why` 随决策进响应体、前端直接显示。
有一条测试拒绝把 id 当理由（`re.fullmatch(r"[a-z_]+", why)` 就红）。

**三、`EVAL_MODE` 放行的是流程，不是记录。** 只有安全类规则 `bypassable=True`
（评测要让被拦的主诉也走完一遍拿到分数），而"本来会被拦"照样如实记在
`safety_flag` 里。非安全类规则（证素为空、验证否决）**不受 EVAL_MODE 影响**。

### 中止的三类不许合并

```
safety   危重     → 要的是让人立刻去急诊，不是换一张方
evidence 依据不足 → 要的是补信息
veto     验证否决 → 要的是重开或人工介入
```

合成一个"失败"的话，响应里只能说"被拦截了"，患者分不出是"你该立刻就医"还是
"系统改不出合规的方"。

## 3. `agent_trace`：把决策说出来

响应体里多了一个 `agent_trace`，每条决策四段分开：

```json
{"rule": "symbolic_veto", "capability": "stop", "capability_label": "中止",
 "stop_kind": "veto", "stop_kind_label": "验证否决",
 "why": "符号验证器给出 veto 级违规（配伍禁忌/超量），重开若干轮之后仍未通过。",
 "detail": "甘草 与 甘遂 属配伍禁忌"}
```

**`why` 是制度、`detail` 是这一次的证据**——合成一句的话，读者分不清"系统一向
这么做"和"这次是因为你说了这句话"。前端把它们渲染成两行（`detail` 轻一档）。

**给所有角色，包括患者。** 患者最需要知道的正是"为什么让我去急诊"，而那句话
就在这里。有一条测试扫 `api/main.py`，确认 `agent_trace` 不在任何一处按角色
摘键的清单里。

界面上它摆在链顶下面、九段上面：先说"这是谁的结论"，再说"怎么得出来的"，
最后才是九段的细节。中止那一条左边是朱砂竖线（它是要被看见的），其余三类用
弱分隔线——**不另起色相**（同 R42 九层那条：色只承担语义）。

## 4. 消除投票痕迹

### 4.1 改的是框架，不是能力

「五家综合」把这份结论说成"几个人拼出来的"——**那是内部机制，不是产品形态**。
总纲 §12 的原话是「能力不删，产品面不露」：

- `run_synthesis` **一行没改**，五家各出一份再融合照旧在跑；
- 谁贡献了哪一步仍在 `physician_influences` 里逐条可查，九段界面照样显示
  「叶天士·取象」这种归属；
- `divergence`（分歧读数）、`herb_jaccard`、`epsilon_online` 与三列对照在
  researcher 角色下照旧完整下发。

变的只有两处措辞：

| 位置 | 改前 | 改后 | 这句话在说什么 |
|---|---|---|---|
| 结论顶上 | 五家综合 | **本次辨证** | 这是**这一次问诊**的辨证结论 |
| 链顶那一行 | 本次引到 N 位医家的医案 | **引用名老中医经验 N 家** | 这一份判断**引用了** N 家的经验 |

前者读起来像"有 N 个人参与了这次判断"（投票），后者说的是引用关系（依据）。
**同一个数、同一份数据，改的是它在产品面上表达的关系。**

为什么是「本次辨证」而不是某个人名或者某个产品名：人名是假的（这份结论不是
哪一位医家给的）；产品名会让这句话变成广告；「本次辨证」如实说出这是什么。

### 4.2 判据：词表一处，全量扫描

词表在 `core.agent.VOTING_WORDS` / `ENSEMBLE_WORDS`，匹配走
`has_voting_language()` 一个函数。测试从词表取词，不手抄。

扫描范围是**会显示出去的那些字**：`app.js` / `graph.js` 的全部字符串字面量
（去掉行注释——注释里必须能提到"五家综合"，那正是在解释为什么改掉它）、
`index.html` 去注释后的正文、两份 S3 prompt（prompt 里的措辞会被模型学进输出，
"综合几家的意见"写在那里，模型就会在 `reasoning` 里写出来，直接落在产品面上）、
以及规则表里每条规则的 `why` 与四个能力的中文名。

### 4.3 名字只写一处

改名时最容易出的事是"有一处漏改"，而漏改的表现是界面上两个地方叫法不一样。
所以 `SYNTHESIS_PHYSICIAN_NAME` 只在 `core/chain.py` 定义；
`core/physicians.py` 的 `SYNTHESIS_DISPLAY["name"]` 置为 `None`，由
`synthesis_display()` 现取（有一条测试断言那个 `None` 还在——它一旦被填回去，
就说明名字又被抄了一份）。截图脚本与 `tests/test_s3_mode.py` 也改成 import 常量。

## 6. 无法完成项

无。

**一处刻意没做的**：没有把 `ask` / `gather` / `verify` 三条规则改成由
`decide()` 来**触发**（现在它们仍然是 `consult()` 按流程直接调，规则表只负责
记录"它发生过"）。理由是那三件事的触发条件天然在各自模块内部（`run_followup`
自己算信息增益、`run_react` 自己决定要不要再走一步），把触发权挪到规则表就会
变成"规则表里放一个空壳条件、真条件还在模块里"——那正是这一轮要消灭的第二处
实现。规则表在这三条上的作用是**命名与解释**，不是控制流，这一点写在
`core/agent.py` 的模块文档里，不是遗漏。
