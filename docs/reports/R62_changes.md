# R62 变更说明

## 做了什么

**前端重写。** `web/product/` 四份新文件：三栏问诊、组方实验室、知识查询
覆盖层。旧 `web/` 一个字没动，内部研究版仍用它；`GET /` 由服务端分流。

**`S3Derived` 补四项**：辨证要点、鉴别、加减建议（可一键写回处方表）、
自评（全是文字，没有可排序的数）。都带默认值，历史录制照常解析。

**三个轻量能力。** 问诊要点改成零 LLM——`question_candidates` 早就按信息
增益算该问什么，0.18 秒对 3 秒预算，每条有可追溯依据。编辑助手与组方检验
关思考低努力，规则层已判过的事摆进 prompt 当既定事实、禁止重判。

**十一条端点**补齐；`explanations` 随结果一次性下发（点术语 ≤100ms 的前提）。

**§11.3 那段静默**：补 `verify_start`/`verify_round`/`verify_done`/
`corroborate_*` 与 `s3_draft`——S3 一解析出来就发，②–⑥ 立刻渲染、
⑦ 标"核对中…"。兜底 120 秒收到 60 秒。

## 修掉四个真 bug

1. `s3_structured` 对患者角色原样下发——扁平那份裁了，五步链没裁。
2. 事件契约测试正则不含数字，`s1/s2/s3_*` 五个事件从没被检查过。
3. `.overlay{display:flex}` 盖过 `[hidden]`：透明覆盖层吃掉所有点击。
4. 设置写入 PUT 写成 POST，切角色点了没反应。

后两个由 `scripts/verify_r62_ui.py`（真浏览器）抓到。第 4 个还暴露出我一条
写松的断言：`#op-record` 本来就不可见，角色没切时它照样绿。

## 验到哪一步

真浏览器在 1920×1080 与 1366×768 各跑一遍、每遍五档缩放。§13.2 的 23 条
**验完 19 条**——第 2、5、6、8、9、10、11、12 条靠注入一份构造好的结果
（这几条的差别完全在前端），测的仍是上线那份 js + css + 真浏览器排版。

它还抓出第三个产品 bug：**改患者信息不重跑规则核查**。医师常是先出方、
再补上妊娠这一项，只在改药时重跑的话那条红条永远不出现——"人这一维"
就只在接口层成立、界面上不成立。

**没验的 4 条**：要真实模型跑一次问诊（10 秒有内容 / 20 秒出证型 /
45 秒方剂完整 / AI 提示的内容）。请在 AutoDL 按 §13.2 第 3、7、13 条过。
