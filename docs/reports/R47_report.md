## 1. §8.1 总开关

### `core/product_mode.py`：唯一分派点

```
PRODUCT_MODE=1（默认）→ 正式版      PRODUCT_MODE=0 → 内部研究版
```

| 函数 | 回答什么 |
|---|---|
| `is_product_mode()` | 这一次运行是不是正式版。**默认 True**，认不出的值按默认走并打一句 stderr |
| `require_internal(feature)` | 内部功能的入口守卫。产品模式下抛 `InternalOnly`；`feature` 不在 `INTERNAL_FEATURES` 里当场 `KeyError` |
| `available_roles()` / `default_role()` | 界面上能选哪几个角色、请求没带 role 时用哪个 |
| `resolve_role(raw)` | 角色标识的唯一解析入口（CLAUDE.md「边界上统一解析」） |
| `product_flags()` | 下发给前端的那一份 |

**为什么是一个模块而不是各处 `os.environ.get`**：要藏的东西有十六条，
散着判断的话以后加第十七条会漏掉其中几处，而漏掉的那几处恰恰是没人盯着的
角落（顶栏折叠起来的那一块、某个角色下才出现的面板）。

**抛错而不是静默返回空**：静默是 demo 味的来源。一个"点了没反应"的按钮比
一个明确说"这里没有这个功能"的 404 更难查，也更像半成品。

### 内部端点 404（不是 403）

403 承认这个端点存在，404 连存在性都不暴露。响应体是
`{"detail": "没有这个功能。"}`——`InternalOnly` 这个词只留在服务端日志里。

覆盖：`/api/usage`、`/api/usage/validate-key`，以及 `/api/eval/*`、
`/api/debug/*` 两个前缀（这台服务上没有这两类端点，**测试仍然覆盖它们**：
将来有人加了，测试会立刻红，而不是等评审时被人在界面上点出来）。

测试 `test_enumerating_routes_finds_no_internal_prefix_open_in_product_mode`
**枚举全部路由**而不是对着一张白名单比——列表会漏掉以后新加的端点。

### 角色解析的位置改了（本轮修掉的一个真 bug）

第一版把 `resolve_role()` 放在 `/api/consult` 的 **return 那一行**。产品模式下
请求 `role=researcher` 的结果是：模型跑完、钱花掉、审计记录写了，**然后**才
404。改到函数第一行；流式端点同理（开流之前解析，不是在 done 事件里）。

### 白名单机制：函数级，不是文件级

`internal-only` 那些块的文案**本来就该带研究词**（用药对照带就是要写"噪声
地板"）。所以 `tests/test_no_demo_artifacts.py` 的
`INTERNAL_RENDERERS` 登记到**函数**这一级：

```
rxCompareHtml / rxBandSvgHtml / epsilonLabel / divergenceBannerText / layerText  → §8.2 第 7 条
demoModeText                                                                     → §8.2 第 3 条
```

只有六个函数。登记表另有两条自检：**条号必须在清单里**（不许拿白名单当垃圾
桶），**函数必须真的存在**（改名之后留在表里的那一条会永远放行一个不存在的
名字，而真正该被扫的新函数没人登记）。

扫描时**只看含中文的字符串字面量**。纯 ASCII 的串在这个前端里几乎全是 DOM
id、CSS 选择器和 option 的 value（`"demo-mode-banner"`、`"hybrid"`），
算进来就得维护一张"这个 id 不算"的例外表，而例外表一长这条约束就废了。
**代价说清楚**：纯英文的界面文案这一层扫不到，由运行层（产品模式截图扫
`innerText`）兜底。

### 本轮扫出来的一处真漏

`describeSafetyFlag()` 那行警告**不在 `internal-only` 块里**（它是安全警告，
任何模式下都必须显示），而原话是「⚠ 评测模式（EVAL_MODE）已开启：…」
——一个内部开关名摆在使用者面前。改成「当前服务运行在一种「命中安全规则也不
中止」的诊断配置下…」，要拦的行为一个字没变。

### 第 26 条的预计剩余时间：口径

**不写死秒数，也不用 R40 压测里的 p50。** 那一组是 `--backend fake` 跑出来的，
量的是服务框架开销，不是真实推理历时——拿它当预计等于用一个不相干的数冒充
实测（「任何数字都必须带对照」那条铁律的反面用法）。

实际做法：**这台部署自己跑过的历时**，存 localStorage，保留最近 20 次，
取中位数。样本不足 3 次时如实说「这台服务还没有足够的历时样本（1/3），
走完这一次之后就能给出预计时间」，不给一个编的秒数。

只有 `done` 计入样本：追问、信息不足、被拦截都没跑完整条链，混进中位数会
让预计时间越来越短，而那不是它变快了。采样点挂在 `setConsultState()` 这
唯一一处，不散到各个调用点。

## 8. 踩的坑（已写进 `data/SOURCES.md` 137–141）

1. **产品模式的默认值放在哪，决定了访问者看到的第一眼。** 等 `/health`
   回来再摘，访问者会先看到半秒的内部界面再看它们消失。
2. **被 CSS 藏起来的 `<option>` 仍然是 select 的 value。** 藏一个*控件的
   取值*跟藏一块*展示内容*是两件事——症状是"界面看起来对了、一点就报错"。
3. **一层"客观校验"叫成"建议"，就变成了诊疗建议。** 内容合规、名字不合规。
4. **`herbs_grounded_ratio = 0` 的两种含义产品面原本分不出来**，因为分辨
   它们的那个字段只下发给研究者角色。
5. **注释里的说明文字让禁词扫描恒红，这是第五次**；而且这次发现**去注释
   不能用正则**——`"https://…"` 会被当成注释开头，静默吃掉半行字符串。
