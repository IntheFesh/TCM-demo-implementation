## 1. `HERB_ALIASES` 从 70 条扩到 291 条

`scripts/build_herb_aliases.py`（新增，零 LLM 调用，纯规则候选生成）读
`cases.json` 里 698 种药名写法，跟本体（`data/standard/materia_medica.jsonl`
1232 味正名）比对，四类规则（产地前缀剥离、部位/修饰后缀剥离、修饰前缀
剥离、子串简称补全）生成候选，输出到 `data/standard/herb_alias_candidates.tsv`
供人工审查——脚本本身**不自动写入** `HERB_ALIASES`。

**这次沙盒里 `cases.json` 是真实数据**（1075 诊次，跟用户真机的数字对得上），
所以下面全部是真实测得的数字，不是估算。

### 1.1 别名表增量的分类计数

| 来源 | 条数 | 说明 |
|---|---|---|
| 算法 high（精确匹配，单条规则） | 44 | 产地前缀 19 + 部位/修饰后缀 16 + 修饰前缀 9，批量确认 |
| 算法 medium（精确匹配，规则叠加≥2层） | 3 | 逐条人工核实 |

| **合计新增** | **221** | 70 → 291 |

`scripts/build_herb_aliases.py` 本轮共生成 235 行候选（覆盖 108 个写法，
high=44/medium=31/low=158，其中 medium/low 部分因为一个写法可能有多条
候选，行数比写法数多）。**只挑了单候选、经人工核实无歧义的那部分合入**；
多候选（如"车前→车前草/车前子"，全草与种子是两个不同部位）、涉及可能
药典分列品种的可疑候选（如"苦葶苈"可能是甜/苦两个品种、"栝蒌皮"的
唯一候选"栝蒌根"其实是根不是皮，见下节"两类被拦下的错配"）一律不收。

### 1.2 47 条人工手补的判断依据（算法覆盖不到的写法，逐条列出）

这些写法算法生成不出候选（多是 2 字异体字、单字截断、或需要跨字符的
类比），靠对照本体正名手工核实后加入：

- **异体字/古称**（写法跟正名完全不共享字符，算法的字符级规则剥不出来，
  靠 TCM 常识核实）：`于术`/`生于术`→白术（"於术"的异体字写法，本体
  已收"於术"）；`茅术`/`生茅术`→苍术（茅山苍术的古称，R59 任务书原文
  给的例子"制茅术"就是这一类）；`焦术`→白术；`山栀`/`黑山栀`/`黑栀皮`→
  栀子（山栀是栀子的古称）；`归须`/`归尾`→当归（"归"截断自"当归"，
  医案原文常见写法）；`金铃子`→川楝子（金铃子散因此得名，经典异名）；
  `香豉`→淡豆豉（本体只收"淡豆豉"，没有裸"豆豉"条目）；`萆`→萆薢
  （单字，疑似古籍抽取时的截断，本体有完整的"萆薢"条目）；`草蔻`→
  草豆蔻；`白蔻`/`白蔻仁`→白豆蔻；`官桂`→肉桂（商品等级古称）；
  `鲜省头草`→佩兰（省头草是佩兰古称）。
- **叠加已收别名再加一层修饰字**（每一层单独看都安全，算法没有把
  "已经是别名目标"再往下叠一层修饰字这一步）：`真山连`/`小川连`→黄连
  （"山连"/"川连"已在基线表里）；`紫浓朴`/`老川朴`→厚朴（"浓朴"/
  "川朴"已收）；`鲜生地`/`小生地`→地黄（"生地"已收）；`藿梗`→藿香
  （"藿香梗"已收，这条少了"香"字）；`杏泥`→杏仁（"杏仁泥"已收，
  少了"仁"字）；`开口吴萸`→吴茱萸、`大云苓片`→茯苓、`带皮苓`→茯苓、
  `炒黑川椒`→花椒（"吴萸"/"云苓"/"茯苓皮"/"川椒"都已在基线表）；
  `晚蚕砂`→原蚕砂（"蚕砂"本轮已收）。
- **裸字/短语默认指向最常见的那味**（无产地/炮制修饰，classical texts
  里默认写法）：`南枣`/`南枣肉`→大枣；`枣`→大枣；`姜汁`/`淡姜`/
  `淡姜渣`/`煨姜`→生姜；`姜夏`→半夏（"姜半夏"的截写）；`安边桂`→肉桂；
  `炒楂肉`→山楂；`炒薏米`/`生薏米`/`生苡仁`→薏苡仁（"薏米"是薏苡仁的
  口语名）；`广皮白`→陈皮（"广皮"已收，叠"白"）；`生杭芍`→白芍
  （"杭芍"="杭白芍"，跟已收的"杭白芍"→白芍同理）；`灶中黄土`→灶心土
  （本体"灶心土"/"伏龙肝"分列两条，写法更贴"灶心土"就近取，不猜
  伏龙肝）。

**特别排除、没有收进去的一条**：`洋参`→西洋参——这条最初被我加进去，
`tests/test_herbs.py::test_distinct_herbs_never_collapse_into_one_name`
当场报错：这条测试和 `core/herbs.py` 现有注释都把"西洋参≠洋参"列为
既有的、必须维持的判断（跟川牛膝≠怀牛膝同一类，R59 任务书 §0.3 原文
也用这一对做例子）。核实后撤回，没有合入。

**特别排除、差点引入的另一条**：`姜`→生姜——加了之后本体正名数从
1232 静默变成 1231（`tests/test_ontology_coverage.py` 的金丝雀测试报错）。
根因：本体的"姜炭"经 `core/herbs.py::_HERB_SUFFIX` 剥掉"炭"后缀会落到
"姜"，一旦"姜"有别名，"姜炭"（止血用）就被连带并进"生姜"（发散用），
两味功用不同的药合并成一条。修法：这条裸字别名不收，只留"姜汁"/
"淡姜"两条有明确上下文的写法（这两条走 `HERB_ALIASES` 直查，不经过
`_HERB_SUFFIX` 剥离，没有这个碰撞风险）。这两个案例的完整记录见
`data/SOURCES.md` 第 157 条。

### 1.3 两类候选生成阶段被拦下的错配（没有合入，是合入前拦下的）

人工审查时发现两类跟"逐字剥产地字"同一性质、但更隐蔽的候选错配，
都已在合入 `HERB_ALIASES` **之前**被拦截（不是先收后撤）：

1. **标记字被子串匹配悄悄跨过**："熟怀地黄"反向子串匹配到"地黄"，会把
   中间的"怀"（产地字）连同"熟"（炮制标记）一起吞掉，而本体里"熟地黄"
   是单独一条正名——丢了"熟"字候选就选错了品种。已在
   `scripts/build_herb_aliases.py::_drops_a_distinguishing_marker` 加了
   针对性拦截：只在本体确实对同一个词根分列"生/熟"两条正名时才拦
   （比如"半夏"没有独立的"熟半夏"条目，这种情况丢"熟"字是安全的，
   不会被误拦）。见 `tests/test_build_herb_aliases.py` 的
   `test_marker_guard_blocks_...`/`test_marker_guard_allows_...` 三条测试。
2. **部位字被后缀剥离悄悄换成别的部位**："栝蒌皮"剥掉"皮"落到"栝蒌"，
   子串匹配到本体唯一收录的"栝蒌根"——"皮"（果皮，清热化痰）跟
   "根"（天花粉，生津润燥）是完全不同的部位，功用也不同。这一类没有
   通用的字符级规则能全部拦住（例如"熟半夏"剥"熟"落到"半夏"是安全的，
   因为本体没有独立的"熟半夏"条目），是人工逐条核实时发现并手动排除的
   （`栝蒌`/`栝蒌皮`/`栝蒌仁`/`栝蒌汁`四个写法，合计 27 次出现，全部
   没有合入，留在 `herb_not_in_ontology.tsv`）。

**药典分列品种反向校验**：`tests/test_herbs.py` 新增
`test_r59_pharmacopoeia_distinct_pairs_stay_apart`（南/北五味子、川/怀
牛膝、川/广木香、生/熟地黄、生首乌/制首乌五对，R59 任务书原文点名的
例子）+ 两条正向断言（`ont.herb("广木香").name == "木香"` 且
`ont.herb("川木香").name == "川木香"`，怀/川牛膝同理）——五对全部维持
分列，扩表前后都不许并成一条。

## 3. R57 判定逻辑三处 bug 修复

原始破损输出（用户真机 `--limit 2` 跑出来的）：

```
## 三条硬指标
- ⏳ C 组验证器一次过率 ≥ A 组（假后端或缺数据，量不到）
- ✅ C 组 rule_refs 完整率 ≥ 0.9（C=1.0）
- ✅ C 与 D 一致率 ≥ 0.9（实测=1.0）
**总判定**：✅ 三条全过
```

三处 bug 和修复：

1. **⏳ 被当成通过**：`build_report()` 原来只看有没有 `False`，没有把
   `None`（未测出）跟 `True` 区分开，导致"⏳+✅+✅"渲染成"✅ 三条全过"。
   修法：`all_gates_passed` 三分——任意一条 `False` → 整体 `False`；
   没有 `False` 但至少一条 `None` → 整体 `None`（⏳ 判不了，报告点名
   哪几条没测出来）；三条都 `True` 才是整体 `True`。
2. **样本量 1 也判通过**："C 与 D 一致率=1（1/1）"，分母 1，被当成通过。
   修法：`eval/ablation/spec.py` 新增 `GATE_MIN_SAMPLE_SIZE = 5`（唯一
   出处），任何一条门的有效样本数低于这个数，一律判 `passed=None`
   （⏳ 样本不足），不管比率是多少。
3. **B 组 rule_refs=1 vs C 组=0.375，误导性对比**：B 组
   `THEORY_LAYER=off`，推导链上根本没有医理规则可引，rule_refs 完整率
   在结构上未定义——不是"B 组比 C 组更完整"，是"这个指标对 B 组不适用"。
   修法：`aggregate()` 新增 `rule_refs_applicable` 判定（`S3_MODE` 不是
   `derived`，或 `THEORY_LAYER=off`，都标"不适用"）+ 具体原因的
   `rule_refs_note`，`to_markdown()` 表格里"不适用"单独标注，脚注列出
   每组的具体原因（不再是一个孤零零的满分数字）。

`tests/test_ablation_r57.py` 新增 8 条测试锁定这三处修复（含 28 条测试
全部通过）。修复前后对比：

```
                        修复前              修复后
⏳+✅+✅ 的总判定       ✅ 三条全过         ⏳ 判不了（点名哪条没测出来）
n=1 时 C-D 一致率      ✅ 通过             ⏳ 样本不足（n=1，要 ≥5）
B 组 rule_refs         1.000（无说明）      不适用（THEORY_LAYER=off，
                                            推导链上没有规则可引）
```
