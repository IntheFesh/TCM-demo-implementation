## 三、前缀和（第 3 条）：先量再决定

**算法。** 一个症状对某个证候的似然只有两种来源：它在这个证候的 `indicates` 边上，
或者没有——没有的一律取钳位后的 `P_UNLISTED`，**同一个常数 q**。
实测：图里 1087 个症状平均只指向 3 个证候（3282 条边 / 1087 个症状），
所以 174 个证候里 171 个走同一个 q。记 S = 列出了的、U = 其余：

```
post_yes_c = p_c·q/p_yes = p_c·ry             （ry = q/p_yes，与 c 无关）
−Σ_U v·log2 v = −ry·(A − A_S) − ry·log2(ry)·(B − B_S)
    A = Σ_全集 p·log2 p、B = Σ_全集 p，**只算一次**
```

U 那一整块退化成两次乘加，内层从 O(证候数) 变成 O(这个症状指向的证候数)。

**1087 条候选 × 6 组证素的前后对照**：

| 比什么 | 结果 |
|---|---|
| 候选集合 | 逐条相同 |
| **整个排名** | 逐条相同 |
| `round(ig, 4)` | 逐条相同 |
| `p_yes` | 逐条相同 |
| 未取整的 ig | 最大绝对差 **3.3e-14**、相对差 **2.2e-11** |
| `if_yes_top` / `if_no_top` | 11 组用例里 1 组有 **3 条**不同（见下） |

**唯一的理论风险已量化**：`ig <= MIN_INFORMATION_GAIN` 这道门槛是 **1e-6**，
而扰动是 **1e-14** 量级——比门槛小 8 个数量级。候选集合逐条相同这一条就是在盯它。

**那 3 条分叉结论。** 逐条打出来是 1 ulp 并列：

```
烦躁易怒 的前三名（未除以 p_yes 的分子）：
    肝胃郁热证  0.0099638125613346565507
    气郁发热证  0.0099638125613346565507
    肝阳上亢证  0.0099638125613346548159   ← 小 1 个 ulp
除以 p_yes 之后三个舍入到同一个 float 0.14038195644659537398
```

教科书写法比的是**商**，三者舍入到同一个值之后"按下标顺序扫、严格大于才换"
选了下标最小的肝阳上亢证；而前缀和算出的 `p_yes` 跟全量求和差 1e-17，
足够让这个舍入翻过来。**修法是比分子而不是比商**——数学序相同，
但分子不含 `p_yes`，"谁赢"不再取决于 `p_yes` 是怎么加出来的。改完从 4 条降到 3 条，
剩下 3 条是教科书那一版**自己的舍入**造成的（它选的候选分子确实小 1 ulp）。

**真正该被记住的不是哪个答案对**：并列到 1 ulp 时"这个问题偏向哪个证候"本身不是
一个有意义的区分——那 3 条的正确读法是"好几个候选分不开"，而这个字段表达不了。
记进 SOURCES 第 78 条。

## 四、两处结构性提速（第 4、5 条）

**批量症状匹配。** `check_residual` 逐条患者症状各扫一遍图里 1087 个标准症状名，
每个名字的并列片段和 SYNONYMS 概念被重算"患者症状条数"次。
`_match_graph_symptoms_many` 把"按名字算一次"提到外层循环——**不是加缓存，
是把循环嵌套的顺序换过来**（CLAUDE.md：demo 阶段不加缓存）。
单条版成了批量版的一层投影，不是第二份实现（第 31 条）。
顺带把 `from core.syndrome_norm import normalize` 从函数体里提到模块级
——它在一次 `check_residual` 里被执行三千多次，每次都要查一遍 `sys.modules`。

逐对验证：图里 1087 个名字 × 8 个患者词 = **8696 对**，新旧结果一处不差。

**修正表的 `books` 列。** R29 把「加外科教材前要先收窄」写在说明列里，
而**说明列不拦任何东西**：谁跑一次 `--layout waike` 就会静默把「疽」（附骨疽、痈疽，
外科的正式病名）改成「疸」。现在两条单字规则钉死在 `neike` 上，
`parse_textbook` 把教材 key 传下去（4 处调用点全传，有判据数）。
**整词规则一律 `*`**：「大便唐薄→大便溏薄」在任何中医文本里都是错的，
安全性不依赖哪本书——只有单字规则才需要钉书名。

## 八、发现但未动

1. **块边界配错位（第七节那 13 条）。** 5 组重名、TB-118 的 definition 吞了三段。
   根因在 `parse_textbook` 的块扫描：它从「临床表现：」往后找「证机概要：」,
   遇到 `end_labels`（常用药/代表方）或下一个「临床表现：」才停。
   原文里有些块的这几个标签顺序被扫描件打乱了。这一轮**没动**：

2. **`data/element_index.json` 在这台机器上不存在**，`build_graph --all` 第三步
   退出码非 0（要 `cases.json`，真实 LLM 抽取，不在版本控制里）。前两步都跑完了。
   **不是这一轮弄坏的**，上机时跟段 5 之后一起跑。
3. **`scope` 仍然是四个单值，没做成集合**（R29 §7.7 记过）。43 条里一条都不需要
   "只管 name 和 disease、不管 symptom"这种组合。**明确不做**：
   CLAUDE.md「不要过度设计」。
4. **`graph_miss_hint()` 每次提示都重数一遍症状节点**（0.3ms，一次问诊最多几次）、
   **`_symptom_counts_by_syndrome_code` 每请求扫一遍 3682 条边**（1.5ms）。
   两处都在 R30 §5 记过，**明确不做**：要再省就得给图建持久索引，
   那是 walking skeleton 之后的事。
5. **并列到 1 ulp 时 `if_yes_top` 表达不了"分不开"**（第三节）。
   真正的修法是让这个字段能说"好几个候选并列"，那是契约变更，要单独一轮。
