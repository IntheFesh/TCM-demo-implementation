# 第零部分 · 产品定位

## 一句话

**把同一个病人，交给三位不同时代、不同学派的中医，看他们怎么各说各话——并且量化"各说各话"到底有多真实。**

## 这个产品独特在哪

市面上的中医 AI 都在做"给我一个答案"。这个做的是**"给我三个答案，并告诉我它们的差异有多少是真的"**。

差异从哪来：

| 医家 | 年代 | 学派 | 用药特征（实测） |
|---|---|---|---|
| 叶天士 | 1667–1746 | 温病 | 吴萸、川楝子、延胡、桂枝木、高良姜、红豆蔻 |
| 吴鞠通 | 1758–1836 | 温病 | 小枳实、真云连、生苡仁、广皮、旋复花、降香末 |
| 张锡纯 | 1860–1933 | 衷中参西 | **生赭石**、生怀山药、天冬、鸡内金（并用西药） |

差异有多真：`ε = 0.2611`——同一位医家自己跑两次的用药差异。**任何低于这条线的"分歧"都是噪声。**
这是这个项目最硬的方法论贡献，也应该是界面上最显眼的东西。

> ⚠ **订正（R11）**：`ε = 0.2611` 是 **2026-09-15 那次 AutoDL 重跑**得到的，
> `eval/epsilon.json` 里 `model` 字段记的是 **deepseek-chat**（在它之前那一版是
> **0.2409**，同一个模型的另一轮——同模型两轮就差了 0.02，这本身就说明 ε 自己也有
> 轮次抖动）。而这个值跑在**思考未受控**的条件下：那时 `_complete` 根本没传
> `thinking`，走的是该模型的默认行为。
>
> 换到 `deepseek-v4-pro` 之后两件事变了：① 它是推理模型，
> **思考模式下 temperature 不生效**——"同样输入不同输出"不再是采样抖动，而是推理
> 路径抖动；② deepseek-chat 已于 2026-09 下线，任何重跑都换了模型。
>
> 所以 **ε 必须按 (model, thinking 设置) 这个二元组分别重测**，一个 ε 值单独出现是
> 没有意义的（见 R12 的 P3、`eval/RESULTS.md` 的 ⚠ 第 4 条）。界面上显示 ε 时必须
> 带上它是哪个模型、哪种 thinking 设置下测的。

## 三类使用者，三种界面形态

| 角色 | 他要什么 | 界面重点 |
|---|---|---|
| 患者 | 我这是什么病，该看哪科 | 病名、科室、红旗症状。**绝对不出方药** |
| 医生 | 处方能不能用，我要改 | 可编辑表格、配伍拦截、导出与审计 |
| 学生 | 为什么这么开 | 君臣佐使、推理路径、三家对照 |
| 研究者 | 数据和证据 | 完整链路、引用、评测指标 |

# 第一部分 · 设计方向：集注

## 为什么是"集注"

中国古籍注疏有一种体例叫**集注**：正文一段，下面并列多位注家对同一段的解读，读者自己比较。
《论语集注》《伤寒论》各家注都是这个形态。

**这个产品就是一份医案集注**：患者主诉是"正文"，三位医家的辨证是"注"。

这个框架不是装饰，它决定了三件事：

1. **正文只有一份，注可以有多份**——主诉居顶且唯一，三家平行并列，没有主次
2. **注与注之间的异同是读者要看的重点**——所以共用药 / 独有药的对照是界面的主角
3. **注要能追到出处**——每条结论可点开看它引了哪条医案原文

## 明确不做的（避免落进通用模板）

- ❌ 米白底 + 高对比衬线大标题 + 陶土色强调（这是当前 AI 生成设计最典型的样子）
- ❌ 深黑底 + 单一亮绿/亮红强调
- ❌ 报纸式发丝线 + 零圆角 + 密集分栏
- ❌ 所有内容切成一模一样的圆角卡片、同一个阴影
- ❌ 全大写英文标签（`SYMPTOMS`）、中间点串联（`A · B · C`）、按钮文字后面加 `→`
- ❌ 小号数据标签用等宽字体

# 第二部分 · 设计系统

## 2.1 色彩

配色取自**中药材与矿物药**，每位医家的色对应他标志性的用药——这不是附会，是实测的用药特征。

### 基础

```css
--paper:      #F2F3EF;   /* 底：草木灰白，微绿调。不是米白，避开模板色 */
--surface:    #FFFFFF;   /* 卡面 */
--surface-2:  #FAFBF8;   /* 次级面：折叠区、表格斑马纹 */
--ink:        #1E211C;   /* 正文：暖黑，不是蓝黑也不是 #111 */
--ink-2:      #4A4E46;   /* 次要文字 */
--muted:      #7C8076;   /* 辅助说明、单位、出处 */
--rule:       #D8DBD2;   /* 分隔线 */
--rule-soft:  #E8EAE4;   /* 弱分隔 */
```

### 三家身份色

```css
--ye:      #2C5F5A;   /* 叶天士 · 青黛 —— 温病轻清 */
--ye-bg:   #E6EFED;
--wu:      #9C6B16;   /* 吴鞠通 · 黄芩 —— 苦辛通降 */
--wu-bg:   #F4EDDF;
--zhang:   #8A4736;   /* 张锡纯 · 赭石 —— 他最标志的药就是生赭石 */
--zhang-bg:#F2E7E3;
```

> 张锡纯的赭石色偏红棕，跟被用滥的陶土色（#D97757）不是一回事——这个更深、更钝，
> 是矿物而非陶器，而且**有实测依据**：他三条医案里生赭石出现三次。

> ⚠ **订正（R11）**：这三组色值**唯一的来源是 `core/physicians.py`**，不在 CSS 里
> 写死。理由是 CLAUDE.md 第 31 条「同一概念的匹配逻辑只能有一处实现」的前端小节：
> **写死的常量也算一处实现**——注册表里加第四位医家时，CSS 里那份副本不会跟着长出来，
> 于是新医家在界面上没有颜色（这个坑已经踩过一次，见 SOURCES.md 第 31 条前端小节）。
> 正确做法：`core/physicians.py` 的每位医家带 `color` 与 `color_bg` 两个字段，
> `/health` 把它们下发，`app.js` 启动时 `documentElement.style.setProperty('--ye', …)`
> 注入 CSS 变量。`app.css` 的 `:root` 里这几个变量声明为空值占位（只为让
> `var(--ye, …)` 有兜底），不写具体色值。

### 语义色

```css
--danger:     #B3261E;   /* 朱砂。配伍禁忌、危重拦截 */
--danger-bg:  #FBEAE8;
--caution:    #8A6D1F;   /* 毒性药材、剂量警告 */
--caution-bg: #F7F1DF;
--verified:   #2C5F5A;   /* 有出处可核（复用青黛） */
```

**色只承担语义，不做装饰。** 一个元素带颜色，必须是因为它属于某位医家，或者它在报警。

### 分歧读数专用

```css
--noise:      #B9BDB3;   /* ε 噪声地板的参考线 */
--real:       #1E211C;   /* 超出噪声地板的真实差异 */
```

## 2.2 字体

两套，分工明确：

```css
--font-classic: "Noto Serif SC", "Source Han Serif SC", "Songti SC", serif;
--font-ui:      "Noto Sans SC", "Source Han Sans SC", -apple-system, "PingFang SC", sans-serif;
--font-num:     "IBM Plex Sans", -apple-system, sans-serif;  /* 数字与拉丁 */
```

**宋体用于"医学内容"**：主诉原文、证型、治法、方名、药名、医案引文。
**黑体用于"界面外壳"**：按钮、标签、表头、提示、导航。

这个分工让界面自己说清楚：**衬线的是中医的话，非衬线的是系统的话。**

> ⚠ **订正（R11）· 离线策略**：这个项目要能断网演示（回放模式的全部意义就在这里），
> 所以字体必须有**不依赖网络的兜底**：
> 1. `@font-face` 从 CDN 取 Noto Serif SC / Noto Sans SC 各 400/600 两档，
>    **必须带 `font-display: swap`**——默认的 `block` 会在取不到时留最多 3 秒空白，
>    断网演示时页面开头就是一片空的。
> 2. 每个 `--font-*` 变量的字体栈里，CDN 字体后面**必须跟系统栈**：
>    `"Songti SC", "SimSun", "Noto Serif CJK SC", serif` / `"PingFang SC",
>    "Microsoft YaHei", "Noto Sans CJK SC", sans-serif`。
> 3. 判据：**断网时页面不得出现空白期或跳字**（swap 会让字形切换一次，这是可接受的；
>    整段空白不可接受）。

### 字号

```
主诉正文      28px / 1.55  宋体 400    ← 页面最大的字，它是"正文"
证型          20px / 1.4   宋体 600
治法          16px / 1.6   宋体 400
方名          17px / 1.4   宋体 600
药名          15px / 1.7   宋体 400
医案引文      14px / 1.75  宋体 400  --ink-2
界面标签      13px / 1.4   黑体 500  --muted
正文说明      14px / 1.65  黑体 400
按钮          14px / 1     黑体 500
数字/指标     15px / 1.2   数字字体 500
```

正文行宽不超过 38 个汉字。

## 2.3 间距与形状

```css
--s1: 4px;  --s2: 8px;  --s3: 12px; --s4: 16px;
--s5: 24px; --s6: 32px; --s7: 48px; --s8: 64px;

--r-sm: 3px;   /* 标签、徽章 */
--r-md: 6px;   /* 按钮、输入框 */
--r-lg: 10px;  /* 卡片 */
```

**圆角按层级区分，不是所有元素一个值**——这是通用模板最明显的特征之一。

**不用阴影做层次**，用底色和边框：

```css
--edge:      1px solid var(--rule);
--edge-soft: 1px solid var(--rule-soft);
```

唯一允许的阴影是浮层（tooltip、侧栏）：`0 2px 16px rgba(30,33,28,.10)`。

## 2.4 动效

**只有三处允许动效，都是回应用户动作的**：

| 场景 | 效果 | 时长 |
|---|---|---|
| 展开/折叠 | 高度 + 透明度 | 180ms ease-out |
| 路径高亮 | 非路径节点降到 0.25 透明度 | 220ms |
| 处方校验反馈 | 警告条从上方滑入 | 160ms |

**页面载入、卡片悬停、分区进场——一律不做动画。** 那是最典型的生成式默认。

尊重 `prefers-reduced-motion: reduce`，此时全部改为瞬时。

### 关键设计决定

**一、三家等宽等高，绝不分主次。** 这是"集注"的核心——没有哪一家是标准答案。
三列之间用 `--rule-soft` 细线分隔，不用卡片包起来（卡片会暗示它们是独立的东西，
而它们是对同一段的三种读法）。

**二、身份色只用在顶部三行**（姓名 / 年代 / 学派 + 一条 3px 顶边），
列内正文全部用 `--ink`。**整列染色会让人看颜色而不看内容。**

**三、用药对照是页面的主角。** 不是大数字配小标签（那是默认做法），而是一条
**点阵对照带**：共用药实心点、各家独有药按各自身份色。一眼看出"共同的少、
各自的多"——这比 `0.53` 这个数字直观得多。

数字放在对照带下面，跟 ε 参考线并列：

```
├───────────┼─────────────────────────────┤
噪声地板 ε=0.26          三家平均差异 0.53
```

**ε 那段用 `--noise` 灰，超出部分用 `--real` 黑**——视觉上直接说明"这一截是真的"。

**四、药材默认只显示君臣 + 前两味佐药**，其余折叠。理由：三列并排时垂直空间是
稀缺资源，而君臣决定了"这一路是什么打法"，佐使是加减。

**五、输入框在最下方。** 因为结果才是主体，输入是动作。第一次进入时（无结果）
输入框居中放大，有结果后收到底部。

### 状态设计

| 状态 | 表现 |
|---|---|
| 首次进入 | 输入区居中，下方三条示例主诉可点击直接填入 |
| 辨证中 | 三列各自显示分步进度（S1 → S2 → S3），**不是一个转圈** |
| 信息不足 | 三列位置显示一句话 + 建议补充的信息，不留空白 |
| 安全拦截 | **整页替换**为拦截说明 + 就医指引，不显示任何方药区域 |
| 追问 | 在对应医家列内弹出问题，其余两列继续等待 |

**安全拦截必须整页替换而不是加个横幅**——研究显示"什么都标红会训练用户忽略标红"。
这个系统只在真危重时打断，所以打断必须是彻底的。

## 3.2 图谱视图

六层，从症状到药材。**默认折叠**，展开后占满宽度。

```
症状 ─→ 证素 ─→ 病名·证型 ─→ 方剂 ─→ 药材
 │                                      （方剂为父框，药材在框内）
 └─ 点击任一症状：三跳高亮到方剂层，其余降到 0.25 透明度
```

### 三个规格

**方剂框的边框区分来源**：
- `classic`（经典方原方）：实线
- `modified`（经典方加减）：虚线
- `composed`（自拟方）：点线

这让"这是仲景的方还是他自己拟的"一眼可辨。

**边的透明度编码 λ1**（医家层权重）。当前语料下 λ1 恒为 0，所有边同一透明度——
**图上要有一行说明**："当前语料中医案术语与国标不对齐，医家层权重为 0，
边权重显示的是标准先验层"。不解释的话评委会以为图没建好。

**布局硬约束**：三位医家 × 三个候选方 = 九个方剂框，纵向空间紧张。
方剂框之间的最小间距需要考虑 cytoscape 的 compound padding（固定屏幕像素，
不随缩放变化），实测需要 60px 的模型坐标间距。

# 第四部分 · 后端架构

## 4.1 五层与各自不可替代的作用

```
安全层    输入侧危重拦截 / 输出侧配伍剂量煎法       唯一不可绕过的硬约束
ReAct     七工具取证，医案层优先                  让模型自己决定还缺什么
推理链    S1 症状标准化 → S2 证素 → S3 按医家开方   把结论拆成可追溯的六步
RAG       dense / bm25 / graph / hybrid          回答"这位医家实际怎么处理"
知识图谱   国标层 / 医案层 / 药理层                 回答"标准怎么规定"
```

## 4.2 检索层设计：为什么必须是混合检索

**实测案例**（这个案例决定了整个检索层的设计）：

主诉「胃脘胀痛，**每因情志不畅而发**」，全库唯一精确命中的医案是
`ye_tianshi-0030-p0-0`（症状含「情志不适即发」）。

```
dense（bge-small-zh）：排第 216 / 495   ← 对「情志不畅」这个特征完全无感
bm25（关键词精确匹配）：排第 2
```

**中医术语的精确匹配能力是语义向量缺的**，所以必须混合。

但混合有两个陷阱：

**陷阱一：融合后用单路阈值过滤。** 如果最终结果要求"dense 分 ≥ 阈值"，
BM25 只能影响排序、不能引入 dense 够不上的条目——等于取消了混合。

**陷阱二：RRF 的排名压平效应。** `RRF_K=60` 时 `1/(60+1)` 和 `1/(60+2)` 只差 1.6%，
dense 第 1 名的位置优势 ≈ bm25 第 2 名的优势。**代数上可证明调小 K 无效**
（K→0 时 dense#1 趋于 1.0，bm25#2 上限 0.5）。

**设计结论**：RRF 融合 + **BM25 top-N 保底**（N=2，且 `min(N, k-1)` 保证不退化成纯 BM25）。
展示分仍用 dense 相似度，但不做准入判断——所以工具描述必须说明
"**score 低不代表不相关**"。

## 4.3 推理链的六步

```
症状 → 证素 → 病名 → 证型 → 治法 → 方剂 → 药材（君臣佐使）
```

每一步带 `rationale`，且 **`rationale` 必须来自原文**（`source_span` 或教材原文），
拿不到就填 `null`——**不许编**。这是"推理"和"匹配"的区别所在。

## 4.4 ReAct 的取证清单

七个工具，**清单必须以医案层为首**：

```
① 医案层（search_cases / query_case_graph）
   这位医家遇到类似症状实际怎么处理 —— 必查，至少一次
② 标准层（lookup_standard）
   核对证型在标准里主症是否齐备 —— 查一次即可
③ 图谱层（query_graph / check_residual）
   确认症状与证素的对应、查漏
```

理由写在 prompt 里给模型看：**国标证候名（"肝胃不和证"）和医家医案里的说法
（"肝木乘土"）是两套术语；查国标能确认标准怎么规定，但开什么方、用哪几味药，
只有这位医家的医案能告诉你。**

两处止损（**是提示不是禁止**，不剥夺模型在特殊病例上的判断）：
- 连续两次查标准证候编号 → 提示"区分编号对开方帮助有限"
- 连续两次 `query_graph` 查不到 → 提示"患者原话多不在国标节点里，改查医案"

## 4.5 安全层

### 输入侧

危重关键词命中 → 直接拒绝，不出方。SDT Test 上拦 10/50，人工复核全部真危重，
**无一误伤**。代价可量化：关闭后分数 +4.56（占满分 9%）。

### 输出侧

| 检查 | 规模 |
|---|---|
| 十八反十九畏 | 24 对 |
| 剂量上限 | 62 味，每条带药典出处注释 |
| 必要煎法 | 39 味（先煎/后下/包煎） |

**生毒药限量设为 0.0**（生附子、生半夏、生川乌、巴豆、红粉）——
意思是"任何标了剂量的内服都判超限"，不是"允许少量"。生品与制品各有限值。

**查不到就留白，不借相近药的数**。理由：剂量上限填错比不填危险，
系统会给出一个"看起来有依据的"错误安全线。

### 医生模式的责任闭环

- 导出端点**服务端重算 safety**，不信客户端传来的判断
- **哈希链审计**，篡改第 N 条时精确报 `seq=N` 且不连累后续
- `override_reason` 是"医生明知有问题仍坚持"的唯一记录

## 4.6 分歧量化

### ε 噪声地板

同一主诉重复 N 次，测同一医家自己跟自己的用药 Jaccard 距离。

**ε 按证型的方剂选择空间分层**：

```
痰饮 / 食滞 / 寒热错杂（经典方几乎唯一）→ ε ≈ 0
肝胃气滞 / 血瘀（可选方十余个）          → ε ≈ 0.5
```

**所以必须逐条配对比较，不能用全局 ε 做减法。** 界面上显示 ε 时，
显示的是**当前这条主诉的** ε，不是全局均值。

### 两两配对

不用 N 方交集（只有三家都用的药才算共同，jaccard 天然偏向 1.0）。
三对分别算，按学派分组：

```
lineage      叶×吴（同为温病派）
cross_school 叶×张、吴×张（跨学派）
year_gap     从生年算（叶×张 193 年，吴×张 102 年）
```

# 第五部分 · 部署形态

## 5.1 三层访问控制

| 层 | 作用 | 默认 |
|---|---|---|
| **BYOK** | 访问者填自己的 key，存 `sessionStorage`，服务端不落盘 | 零成本无上限 |
| **共享额度** | 不填 key 的用项目的 | 每 IP 5 次/天，全局 200 次/天 |
| **用量看板** | `/api/usage` + 前端显示剩余次数 | 80% 预警，100% 降级 |

**四条硬要求**：
1. **请求前拦截**——被拦的请求不产生费用
2. **按 `llm_calls` 计量不是按请求数**——ReAct 开关差 3 倍（6 次 vs 20 次）
3. **超限降级到回放而不是报错**——访问者仍能看到预录主诉的完整效果
4. BYOK 只接受 `sk-` 格式，**不做通用代理**

> ⚠ **订正（R11）· 状态从「方案已定，未实施」改为「已实施」**（R10 之后的 `3b958af`，
> 即 D1/F1 那一轮）。落地时确定的几件事，写在这里免得下一轮又当成待办：
>
> - **`TRUSTED_PROXY_HOPS` 默认 0，即默认不读 `X-Forwarded-For`。** 直接信任 XFF
>   等于把限额送人——任何人加一个头就换一个"IP"。只有部署在自己的反代后面时才设成
>   反代跳数（nginx 一层就是 1），此时从右往左数第 N 跳才是真实客户端。
> - 三个额度变量：`QUOTA_PER_IP_DAILY_CALLS`（默认 5）、`QUOTA_GLOBAL_DAILY_CALLS`
>   （默认 200）、`QUOTA_MAX_TRACKED_IPS`（默认上限，防止用海量伪造 IP 把内存撑爆）。
> - **额度的单位是 `llm_calls` 不是请求数**，所以扣费发生在问诊结束、拿到真实调用数
>   之后；请求前先按"这次最少会花几次"预扣，不够就直接拦。
> - `FORCE_REPLAY=1` 强制全站走回放（演示日用）。

### 前端的 BYOK 入口

放在顶栏右侧，默认收起为一行小字「用自己的 API key（不限次数）」。
点开是一个输入框 + 一句说明：

> 你的 key 只在本次请求中转发给 DeepSeek，不会存储在服务器上。
> 关闭标签页后即清除。

**不要做成弹窗**，不要在首次进入时拦路。

# 第七部分 · 不可妥协的设计约束

这七条是这个产品的骨架，任何改动不得违反：

1. **三家平等**。没有哪一家是"正确答案"，界面上不得出现主次、排名、推荐。
2. **分歧必须带 ε**。任何展示医家差异的地方，都要同时给出当前主诉的噪声地板。
   没有 ε 的差异数字是误导。
3. **患者模式不出方药**。这是安全边界，从数据构造层就断掉，不是前端隐藏。
4. **危重拦截整页替换**。不是加个横幅——什么都标红等于什么都没标。
5. **每条结论可追溯**。证型、治法、方药都要能点开看引了哪条医案原文。
6. **演示模式必须自报**。回放的结果不得伪装成实时调用。
7. **色只承担语义**。带颜色 = 属于某位医家，或者在报警。不做装饰性配色。

# 第八部分 · 第四 / 第五位医家策略（§8）

> 本节是 R11 新增，不是原总纲的内容。起因：用户明确要求把李可医案、王云启医案
> **拉进训练**（"李可医案非常重要"），而这两位一旦进了 `core/physicians.py`，
> 三列集注就会变成五列——那会直接破坏 §7 第 1 条（三家平等）赖以成立的版面。

## 判决：注册但不参与集注

```python
"li_ke":      {..., "enabled": False, "source": "李可医案（data/local_corpora/）"}
"wang_yunqi": {..., "enabled": False, "source": "王云启医案（data/local_corpora/）"}
```

`enabled` 这个字段回答的是**"要不要在三列集注里占一列"**，不是"这位医家的数据要不要用"。
两件事必须分开，否则只能二选一：要么界面被撑坏，要么语料被浪费。

| 场景 | `enabled=False` 的医家参不参与 |
|---|---|
| 三列集注（问诊页主区） | **不参与**——版面与 §7 第 1 条 |
| 检索语料（`search_cases(physician="li_ke")`） | 参与 |
| 训练导出（`export_sft`） | 参与，且**默认包含** |
| 图谱医案层 | 参与 |
| 学生 / 研究者模式的「参考医家」引用区 | 参与，**不占列**，折叠在三列之下 |
| ε / E3 / E4 / E8 / E9 / SDT 评测 | 不参与（换了医家集合的数字跟旧的不可比） |

## 两个入口，禁止别处自己过滤

```python
physicians_enabled()   # 参与集注的（当前三位）
physicians_all()       # 注册表全部（当前五位）
```

**不许任何地方写 `{k: v for k, v in PHYSICIANS.items() if v["enabled"]}`。**
这正是第 31 条纪律说的"同一概念只能有一处实现"：过滤条件哪天变了
（比如加一个"仅训练"的第三档），散在十处的推导式不会跟着变。

## 界面上的「参考医家」形态

折叠区，标题「参考医家（不参与三家对照）」，每位医家 top-3 相关医案引用，
带身份色的一条左边框。**含十八反配伍的医案必须带那句固定提示**
（常量定义在 `core/safety_output.py`，训练语料与界面共用同一句，见 §9 之后的
R18 说明）——李可用药有其学术依据，但本系统的安全层按药典拦截，两件事都要说清。

# 第九部分 · 性能预算（§9）

> 本节是 R11 新增。没有预算的"优化"没法验收——"快了一点"不是判据。
> 每一条都有对应的测量脚本，数字由脚本产出，不靠手掐表。

| # | 项目 | 预算 | 怎么量 |
|---|---|---|---|
| 1 | 热启动（第二次起进程） | ≤ 20 s | `python -m scripts.bench_startup`（跑两次进程，看第二次） |
| 2 | 一次问诊，不开 ReAct | ≤ 90 s | `python -m scripts.bench_consult --repeat 3 --no-react` |
| 3 | 一次问诊，开 ReAct | ≤ 240 s | `python -m scripts.bench_consult --repeat 3 --react` |
| 4 | 图谱浏览器首屏 | ≤ 1 s | 浏览器 Performance 面板 / Playwright 计时 |

**基线（改动前，2026-09-15 实测）**：启动 135 s、不开 ReAct 一次问诊 394.6 s
（其中三位医家的 S3 串行约 198 s）、单次调用 66 s。

**预算的三个前提必须写清楚，不然数字无法复现**：

1. **模型**：`deepseek-v4-pro`。换模型这几个数全部作废（deepseek-chat 已下线，
   旧数字没有一个是可直接比较的）。
2. **thinking 设置**：S1/S2/追问/ReAct 关思考，S3 按 `S3_THINKING`（默认 `enabled`
   + `reasoning_effort=high`）。**关掉 S3 的思考会明显更快，但那是另一组数**——
   `manifest.thinking_by_step` 记的就是这个，两组数不许混着引。
3. **并发**：问诊内部三位医家并发（`ThreadPoolExecutor`），进程级同时在途的 LLM
   调用数由 `LLM_MAX_INFLIGHT`（默认 6）封顶。**4 个问诊槽 × 3 位医家 = 12 路**
   会撞 DeepSeek 的速率限制，所以这两个闸是两件事，不能只留一个。

**预算不达标时怎么办**：如实报出实测值和差距，**不许调 `--repeat` 或换一条更短的
主诉把数字凑进预算**。预算是用来暴露问题的，不是用来交差的。

# 第十部分 · 这套系统现在是什么（§10，R39 收口）

> 本节是 R39 新增，收 R32~R38 那七轮的口。它回答三个问题：**跟别的路线比，
> 这套东西独特在哪；哪些数已经量到了、哪些还是 ⏳；以及它明确做不到什么。**
> 每一句带数的话都能在 `eval/RESULTS.md` 里找到对应的行和上机命令。

## 10.1 四行对比：同一个问题，四条路线

问题：**患者一段主诉，给出有依据的辨证与方药。**

| 路线 | 它给什么 | 它给不了什么 | 本项目的对应物 |
|---|---|---|---|
| ① 通用大模型直接问 | 一段流畅的辨证文字，几秒出 | **没有出处**——引的医案号可能是编的；同一条主诉两次答案可能相反，而没有基准能判断这算不算分歧 | 每条结论必须引真实医案 id（`cited_case_ids` 过滤检索结果，编的进 `hallucinated`）；分歧度跟噪声地板 ε 比，不裸报 |
| ② 检索增强（RAG） | 相关医案原文 + 一段总结 | **检索到的不等于用上的**：拿了 3 条医案，答案里哪一句来自哪一条说不清；也不知道模型是不是在照抄最长的那条 | 五步链逐段标出处（`from_organs` / `from_syndrome` / `from_method`），药味带本体引用，`herbs_grounded_ratio` 报"这张方有多少味说得出出处" |
| ③ 开源中医模型（BianCang / ShizhenGPT 等） | 中医语域内更地道的表述 | **拿不到它为什么这么说**：模型权重里的知识没法回指到某本书某一页；也没有"这张方能不能发"的硬拦截 | 本体锚定层（本草 1232 / 方剂 235）+ 符号验证器七条规则 + 安全否决在证素推断之前 |
| ④ **本项目** | 一条九段的推理链：主诉 → 证素 → 追问 → 脏腑 → 证型 → 治法 → 方剂 → 药味 → 校验与出处 | **不是诊断工具**：它模拟的是古代医家的思路，不替代执业医师；本体覆盖有长尾缺口（见 10.3） | — |

**这张表不是宣传语**：①②③ 每一行的"给不了什么"都对应本项目里一个具体的机制，
而那个机制有它自己的数（下一节）。没有数的机制不写进这张表。

## 10.3 明确做不到的三件事

1. **不是诊断工具。** 页面第一行就写着"教学与研究用途，非诊断工具，
   不能替代执业医师"，安全否决拦下的请求不产出任何方药。
2. **本体有长尾缺口。** 医案语料里 578 种药名，本体查得到 230 种（39.8%）；
   按出现次数是 70.4%——常用药覆盖得好，古籍特有写法（「云苓块」「广皮炭」）
   覆盖差。**这两个数必须一起报**，只报一个会各自误导一个方向。
3. **名医只有五位，用药规律只覆盖三位。** 五位里李可、王云启的医案没有走过
   LLM 抽取（`out_of_scope`，肿瘤科不在脾胃门），所以 R35 挖出来的 1924 条
   用药规律里没有他们；证型档实际只有「悬饮」够 support。

## 10.4 这七轮留下的方法论（四条）

1. **每个数必须带它的对照**——没有基准的数字在这个项目里等于没有意义
   （分歧度带 ε、比率带分母、比较带同口径前提）。
2. **"判据全绿"不等于"东西是对的"**——R37 那四张空白截图全部通过了当时的判据，
   因为判据查的是类名和 computedStyle，而它们在 `display:none` 的元素上照样正确。
3. **同一个概念只能有一处实现**——匹配逻辑、中文名映射、分母口径，
   第二处实现不会报错，它只会在某一天给出跟第一处相反的答案。
4. **量不到就标 ⏳ 并附上机命令**——不编、不估、不拿模拟值顶替真机数。
