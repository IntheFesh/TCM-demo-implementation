# 第零部分 · 产品定位

## 一句话

**把同一个病人交给三位不同时代、不同学派的中医，看他们如何各自辨证——并量化这些差异有多少是真实的。**

## 这个产品独特在哪

常见的中医 AI 给出"一个答案"。本系统给出**三位医家的答案，并说明它们之间的差异有多少超出了
系统自身的随机波动**。

差异的来源：

| 医家 | 年代 | 学派 | 用药特征（取自医案） |
|---|---|---|---|
| 叶天士 | 1667–1746 | 温病 | 吴萸、川楝子、延胡、桂枝木、高良姜、红豆蔻 |
| 吴鞠通 | 1758–1836 | 温病 | 小枳实、真云连、生苡仁、广皮、旋复花、降香末 |
| 张锡纯 | 1860–1933 | 衷中参西 | **生赭石**、生怀山药、天冬、鸡内金（并用西药） |

差异有多真：用**噪声地板 ε** 衡量——同一位医家对同一条主诉重复推理时自己跟自己的用药差异。
低于这条线的"分歧"是噪声。ε 按「主诉 × 医家」逐条估计，并且与模型和思考设置绑定：换模型或换
思考设置都要重新估计，界面显示 ε 时标明它是在哪个模型、哪种思考设置下测得的（当前数值见
`eval/RESULTS.md`）。

## 默认的推理流程

产品默认（`S3_MODE=derived`）的推理链分三相：

1. **演绎推导**：按医理规则（`data/standard/tcm_theory.jsonl`）与本草/方剂本体，从症状、证素推到
   病位、证型、治法、方剂与药味，每一步引用规则或标记"依据不足"；这一相不检索医案。
2. **符号验证**：`core/formula_verifier.py` 逐条核对推导结果（配伍禁忌、剂量、归经、寒热、功效与
   治法、君臣佐使等），不通过则否决或回灌给模型修订；无法验证的规则单独列出。
3. **医案佐证**：推导定型之后检索各医家的医案库，看历史上是否有相近的治法与用药（一致 / 不一致 /
   无先例），只作为事后佐证，不回头修改推导。

`S3_MODE=legacy` 时三位医家各自依据自己的医案辨证开方，界面并列三列（集注，见第三部分），
`eval/RESULTS.md` 中的 E3/E4/E8/E9 在这一模式下测得；`S3_MODE=structured` 输出一份综合多家经验的
结论。结论只有一份时（derived / structured），问诊页按「主诉 → 证素 → 追问 → 病变脏腑 → 证型 →
治法 → 方剂 → 药物组成 → 校验与出处」九段纵向展示。

## 使用者与界面形态

| 角色 | 需要什么 | 界面重点 |
|---|---|---|
| 患者 | 我这可能是什么病、该看哪科 | 病名、科室、红旗症状。**不出方药** |
| 医生 | 处方能不能用，我要修改 | 可编辑表格、配伍拦截、导出与审计 |
| 学生 | 为什么这么开 | 君臣佐使、推理路径、三家对照 |
| 研究者 | 数据和证据 | 完整链路、引用、评测指标 |

# 第一部分 · 设计方向：集注

## 为什么是"集注"

中国古籍注疏有一种体例叫**集注**：正文一段，下面并列多位注家对同一段的解读，读者自己比较。
《论语集注》、《伤寒论》各家注都是这个形态。

**这个产品就是一份医案集注**：患者主诉是"正文"，三位医家的辨证是"注"。这个框架决定了三件事：

1. **正文只有一份，注可以有多份**——主诉居顶且唯一，三家平行并列，没有主次
2. **注与注之间的异同是读者要看的重点**——所以共用药 / 独有药的对照是界面的主角
3. **注要能追到出处**——每条结论可点开看它引了哪条医案原文

## 明确不做的

- ❌ 米白底 + 高对比衬线大标题 + 陶土色强调
- ❌ 深黑底 + 单一亮绿/亮红强调
- ❌ 报纸式发丝线 + 零圆角 + 密集分栏
- ❌ 所有内容切成一模一样的圆角卡片、同一个阴影
- ❌ 全大写英文标签（`SYMPTOMS`）、中间点串联（`A · B · C`）、按钮文字后面加 `→`
- ❌ 小号数据标签用等宽字体

# 第二部分 · 设计系统

## 2.1 色彩

配色取自**中药材与矿物药**，每位医家的颜色对应其标志性的用药。

### 基础

```css
--paper:      #F2F3EF;   /* 底：草木灰白，微绿调 */
--surface:    #FFFFFF;   /* 卡面 */
--surface-2:  #FAFBF8;   /* 次级面：折叠区、表格斑马纹 */
--ink:        #1E211C;   /* 正文：暖黑 */
--ink-2:      #4A4E46;   /* 次要文字 */
--muted:      #7C8076;   /* 辅助说明、单位、出处 */
--rule:       #D8DBD2;   /* 分隔线 */
--rule-soft:  #E8EAE4;   /* 弱分隔 */
```

### 医家身份色

| 医家 | 色名 | 主色 | 底色 |
|---|---|---|---|
| 叶天士 | 青黛（温病轻清） | `#2C5F5A` | `#E6EFED` |
| 吴鞠通 | 黄芩（苦辛通降） | `#9C6B16` | `#F4EDDF` |
| 张锡纯 | 赭石（他最标志性的药是生赭石） | `#8A4736` | `#F2E7E3` |

**身份色唯一的来源是 `core/physicians.py`**：每位医家带 `color` 与 `color_bg` 两个字段，`/health`
下发，`app.js` 启动时用 `documentElement.style.setProperty` 注入为 `--phys-<id>` CSS 变量。CSS 里
不写具体色值——写死的常量也算一处实现，注册表里增加医家时，CSS 里的副本不会随之增加。

### 语义色

```css
--danger:     #B3261E;   /* 朱砂。配伍禁忌、危重拦截 */
--danger-bg:  #FBEAE8;
--caution:    #8A6D1F;   /* 毒性药材、剂量警告 */
--caution-bg: #F7F1DF;
--verified:   #2C5F5A;   /* 有出处可核 */
```

**色只承担语义，不做装饰。** 一个元素带颜色，必须是因为它属于某位医家，或者它在报警。

### 分歧读数专用

```css
--noise:      #B9BDB3;   /* ε 噪声地板的参考线 */
--real:       #1E211C;   /* 超出噪声地板的真实差异 */
```

## 2.2 字体

两套，分工明确：

```css
--font-classic: "Noto Serif SC", "Source Han Serif SC", "Songti SC", serif;
--font-ui:      "Noto Sans SC", "Source Han Sans SC", -apple-system, "PingFang SC", sans-serif;
--font-num:     "IBM Plex Sans", -apple-system, sans-serif;  /* 数字与拉丁 */
```

**宋体用于"医学内容"**：主诉原文、证型、治法、方名、药名、医案引文。
**黑体用于"界面外壳"**：按钮、标签、表头、提示、导航。
衬线的是中医的话，非衬线的是系统的话。

**离线策略**：录制回放模式要能在断网时运行，所以字体不能依赖网络。

1. 中文字体使用仓库内的子集化 woff2（`scripts/subset_fonts.py` 生成），`@font-face` 必须带
   `font-display: swap`——默认的 `block` 会在取不到字体时留出空白期。
2. 每个 `--font-*` 变量的字体栈里，网络字体后面都跟系统栈：
   `"Songti SC", "SimSun", "Noto Serif CJK SC", serif` / `"PingFang SC", "Microsoft YaHei",
   "Noto Sans CJK SC", sans-serif`。
3. 判据：断网时页面不出现空白期（字形切换一次可以接受，整段空白不可以）。

### 字号

```
主诉正文      28px / 1.55  宋体 400    ← 页面最大的字，它是"正文"
证型          20px / 1.4   宋体 600
治法          16px / 1.6   宋体 400
方名          17px / 1.4   宋体 600
药名          15px / 1.7   宋体 400
医案引文      14px / 1.75  宋体 400  --ink-2
界面标签      13px / 1.4   黑体 500  --muted
正文说明      14px / 1.65  黑体 400
按钮          14px / 1     黑体 500
数字/指标     15px / 1.2   数字字体 500
```

正文行宽不超过 38 个汉字。

## 2.3 间距与形状

```css
--s1: 4px;  --s2: 8px;  --s3: 12px; --s4: 16px;
--s5: 24px; --s6: 32px; --s7: 48px; --s8: 64px;

--r-sm: 3px;   /* 标签、徽章 */
--r-md: 6px;   /* 按钮、输入框 */
--r-lg: 10px;  /* 卡片 */
```

**圆角按层级区分，不是所有元素一个值。**

**不用阴影做层次**，用底色和边框：

```css
--edge:      1px solid var(--rule);
--edge-soft: 1px solid var(--rule-soft);
```

唯一允许的阴影是浮层（tooltip、侧栏）：`0 2px 16px rgba(30,33,28,.10)`。

## 2.4 动效

**只有三处动效，都是回应用户动作的**：

| 场景 | 效果 | 时长 |
|---|---|---|
| 展开/折叠 | 高度 + 透明度 | 180ms ease-out |
| 路径高亮 | 非路径节点降到 0.25 透明度 | 220ms |
| 处方校验反馈 | 警告条从上方滑入 | 160ms |

页面载入、卡片悬停、分区进场不做动画。尊重 `prefers-reduced-motion: reduce`，此时全部改为瞬时。

# 第三部分 · 页面设计

## 3.1 问诊页（主界面）

结论只有一份时（默认的推导模式）问诊页是一条九段的纵向链，段号显式、顺序固定——先说依据，再说
结论。下面描述多位医家并列（`S3_MODE=legacy`）时的集注版面。

### 布局：正文在上，三注并列

```
┌───────────────────────────────────────────────────────────────┐
│  名医辨证对照                          研究者 ▾   默认检索 ▾     │  56px
│  教学与研究用途，非诊断工具                                      │
├───────────────────────────────────────────────────────────────┤
│                                                                │
│   胃脘胀痛，食后加重，嗳气泛酸，每因情志不畅而发，纳差，           │  ← 28px 宋体
│   舌淡红苔薄白，脉弦。                                          │     这是"正文"
│                                                                │
│   ┌──────────────────────────────────────────────────┐        │

│   │  共用 ●●  叶独有 ●●●●●  吴独有 ●●●●  张独有 ●●●●●●   │        │     是可视化

├──────────────────┬──────────────────┬─────────────────────────┤
│ 叶天士 1667-1746  │ 吴鞠通 1758-1836  │ 张锡纯 1860-1933         │

│ 治法              │ 治法              │ 治法                     │
│ 方名              │ 方名              │ 方名                     │
│ 君  药 剂量        │ 君  药 剂量        │ 君  药 剂量               │
│ 臣  …             │ 臣  …             │ 臣  …                    │
│     ⋯ 展开其余药味  │     ⋯ 展开其余药味  │     ⋯ 展开其余药味        │

└──────────────────┴──────────────────┴─────────────────────────┘
│  推理链 · 图谱 · 取证过程                                   展开 ▾ │
├───────────────────────────────────────────────────────────────┤
│  输入主诉                                            [ 辨证 ]   │
└───────────────────────────────────────────────────────────────┘
```

### 关键设计决定

**一、三家等宽等高，不分主次。** 这是"集注"的核心——没有哪一家是标准答案。三列之间用
`--rule-soft` 细线分隔，不用卡片包起来（卡片会暗示它们是独立的东西，而它们是对同一段的三种读法）。

**二、身份色只用在顶部**（姓名 / 年代 / 学派 + 一条 3px 顶边），列内正文全部用 `--ink`。
整列染色会让人看颜色而不看内容。

**三、用药对照是页面的主角。** 一条**点阵对照带**：共用药实心点、各家独有药按各自身份色，
一眼看出"共同的少、各自的多"。数字放在对照带下面，与 ε 参考线并列；**ε 那段用 `--noise` 灰，
超出部分用 `--real` 黑**，视觉上直接说明"这一截是真的"。

**四、药材默认只显示君臣 + 前两味佐药**，其余折叠。三列并排时垂直空间稀缺，而君臣决定了
"这一路是什么打法"，佐使是加减。

**五、输入框在最下方。** 结果是主体，输入是动作。第一次进入时（无结果）输入框居中放大，
有结果后收到底部。

### 状态设计

| 状态 | 表现 |
|---|---|
| 首次进入 | 输入区居中，下方三条示例主诉可点击直接填入 |
| 辨证中 | 三列各自显示分步进度（S1 → S2 → S3），不是一个转圈 |
| 信息不足 | 三列位置显示一句话 + 建议补充的信息，不留空白 |
| 安全拦截 | **整页替换**为拦截说明 + 就医指引，不显示任何方药区域 |
| 追问 | 在对应医家列内弹出问题，其余两列继续等待 |

安全拦截整页替换而不是加一条横幅：什么都标红会训练用户忽略标红，这个系统只在真正危重时打断，
所以打断必须彻底。

## 3.2 图谱视图

九层，从症状到君臣佐使（层号与层名由 `api/main.py` 的 `CHAIN_LAYERS` 定义，随响应的
`graph.layers` 下发，前端不写死）。**默认折叠**，展开后占满宽度。

```
症状 → 脏腑 → 病性 → 证型 → 病机 → 治则 → 治法靶位 → 方剂 → 君臣佐使
                                               （方剂为父框，药材在框内）
点击任一症状：顺着边一路高亮到方剂层，其余节点降到 0.25 透明度
```

### 三个规格

**方剂框的边框区分来源**：
- `classic`（经典方原方）：实线
- `modified`（经典方加减）：虚线
- `composed`（自拟方）：点线

**边的透明度编码 λ1**（医家层权重）。医案术语与国标不对齐时 λ1 接近 0，所有边透明度相同——
图上有一行说明（文字由 `offline/graph_stats.lambda1_note()` 生成、经 `/health` 下发），说明此时边权重
显示的是标准先验层。

**布局**：按层固定列，层内次序由 dagre 计算；方剂框之间的间距要考虑 cytoscape 的 compound padding
（固定屏幕像素，不随缩放变化）。

### 交互序列

```
改剂量 → 400ms 防抖 → 后端校验
加甘草 + 海藻 → 配伍禁忌红条从上方滑入（160ms）
点导出 → 被拒绝，红条下方出现「坚持导出的理由」输入框
填理由 → 导出成功 → 药房格式文本 + 审计编号
```

导出被拒绝时不禁用按钮——禁用按钮不告诉人为什么。按钮保持可点，点了给出明确的拒绝原因和下一步。

**药房格式文本用等宽对齐**（这是唯一使用等宽字体的地方，因为它要对齐）：

```
瓜蒌薤白半夏汤                       7 剂
  瓜蒌     20g
  薤白      9g
  半夏      9g
用法：水煎服，每日1剂，分2次温服
```

## 3.4 学生模式

在三列基础上加三样：

**一、君臣佐使分组显示**，君药加粗。

**二、点症状的路径高亮**。点一个症状，整条链路亮起来，跨越三位医家的全部候选方——这个交互
说明系统在推理，而不是在检索。

**三、推理过程默认展开**（研究者模式默认折叠）。学生要看的就是过程。

```
│  · 呕血或解黑便                                 │
│  ─────────────────────────────────────         │
│                                                │
│  这不是诊断。中医辨证需要面诊，                   │
│  这里只帮你判断该看哪个科。                       │
└───────────────────────────────────────────────┘
```

**红旗症状必须在首屏，不能折叠。** 紧急度为高（胸痹、吐血、便血等）时只显示就医指引，
不提供任何用药或食疗建议。

# 第四部分 · 后端架构

## 4.1 五层与各自不可替代的作用

```
安全层    输入侧危重拦截 / 输出侧配伍剂量煎法       唯一不可绕过的硬约束
ReAct     多工具取证，医案层优先                  让模型自己决定还缺什么
推理链    S1 症状标准化 → S2 证素 → S3 辨证开方     把结论拆成可追溯的步骤
检索      full_context / dense / bm25 / graph / hybrid   回答"这位医家实际怎么处理"
知识图谱   国标层 / 医案层 / 药理层                 回答"标准怎么规定"
```

## 4.2 检索层：为什么必须是混合检索

中医术语的精确匹配是语义向量的短板。以主诉「胃脘胀痛，**每因情志不畅而发**」为例，语料中症状
含「情志不适即发」的医案 `ye_tianshi-0030-p0-0` 在 BM25（关键词匹配）的结果里排得很靠前，在
dense（语义向量）的结果里却排得很靠后——语义向量对这个特征不敏感。`scripts/verify_hybrid_fusion.py`
可以打印这条医案在各路检索中的名次。

混合检索有两个陷阱：

**陷阱一：融合后用单路阈值过滤。** 如果最终结果要求"dense 分 ≥ 阈值"，BM25 只能影响排序、
不能引入 dense 够不上的条目，等于取消了混合。

**陷阱二：RRF 的排名压平效应。** RRF 只看名次，`RRF_K` 较大时相邻名次的分数几乎相同，dense
第 1 名的优势与 BM25 第 2 名相当；调小 K 也不能让 BM25 的强匹配稳定进入结果。

**设计结论**：RRF 融合 + **BM25 top-N 保底**（N=2，且不超过 k−1，不退化成纯 BM25）。展示分仍用
dense 相似度，但不做准入判断——所以工具描述写明"**score 低不代表不相关**"。

默认检索模式 `full_context` 把单个医家的全部医案放进提示词（利用前缀缓存），其余四种模式各取
少量参考医案；五种模式都会在参考医案之前放入本草/方剂知识块。

## 4.3 推理链的步骤

```
症状 → 证素 → 病名 → 证型 → 治法 → 方剂 → 药材（君臣佐使）
```

每一步带 `rationale`，且 **`rationale` 必须来自原文**（`source_span` 或教材原文），拿不到就填
`null`，不编造。这是"推理"和"匹配"的区别所在。

## 4.4 ReAct 的取证清单

**清单以医案层为首**：

```
① 医案层（search_cases / query_case_graph）
   这位医家遇到类似症状实际怎么处理 —— 必查，至少一次
② 标准层（lookup_standard）
   核对证型在标准里主症是否齐备 —— 查一次即可
③ 图谱层（query_graph / check_residual）
   确认症状与证素的对应、查漏
```

理由写在 prompt 里给模型看：国标证候名（「肝胃不和证」）和医家医案里的说法（「肝木乘土」）
是两套术语；查国标能确认标准怎么规定，但开什么方、用哪几味药，只有这位医家的医案能回答。

两处止损（**是提示不是禁止**，不剥夺模型在特殊病例上的判断）：
- 连续两次查标准证候编号 → 提示"区分编号对开方帮助有限"
- 连续两次 `query_graph` 查不到 → 提示"患者原话多不在国标节点里，改查医案"

## 4.5 安全层

### 输入侧

危重关键词命中 → 直接拒绝，不出方。在 TCMEval-SDT 上，安全否决拦下的记录交空答案；关闭否决与
开启否决的分数并列报告，差值就是安全设计的代价（见 `eval/RESULTS.md`）。

### 输出侧

| 检查 | 实现 |
|---|---|
| 十八反十九畏 | `core/safety_output.py::INCOMPATIBLE_PAIRS` + 别名归类 |
| 剂量上限 | `DOSE_LIMITS`，每条带药典出处注释 |
| 必要煎法 | 先煎/后下/包煎表 |

**生毒药限量设为 0.0**（生附子、生半夏、生川乌、巴豆、红粉）——意思是"任何标了剂量的内服都判
超限"，不是"允许少量"。生品与制品各有限值。

**查不到就留白，不借相近药的数**：剂量上限填错比不填危险，系统会给出一个"看起来有依据的"错误
安全线。

### 医生模式的责任闭环

- 导出端点**服务端重算 safety**，不信客户端传来的判断
- **哈希链审计**，篡改第 N 条时精确报 `seq=N` 且不连累后续
- `override_reason` 是"医生明知有问题仍坚持"的唯一记录

## 4.6 分歧量化

### ε 噪声地板

同一主诉重复推理 N 次，测同一医家自己跟自己的用药 Jaccard 距离。

**ε 随证型的方剂选择空间变化**：经典方几乎唯一的证型（痰饮、食滞、寒热错杂）ε 接近 0；可选方
很多的证型（肝胃气滞、血瘀）ε 明显更高。所以必须逐条配对比较，不能用全局 ε 做减法。界面上显示
的是**当前这条主诉的** ε，不是全局均值。

### 两两配对

不用 N 方交集（只有三家都用的药才算共同，距离天然偏大）。三对分别计算，按学派分组：

```
lineage      叶×吴（同为温病派）
cross_school 叶×张、吴×张（跨学派）
year_gap     生年之差
```

# 第五部分 · 部署形态

## 5.1 三层访问控制

| 层 | 作用 | 默认 |
|---|---|---|
| **BYOK** | 访问者填自己的 key，存 `sessionStorage`，服务端不落盘 | 不计入站点额度 |
| **共享额度** | 不填 key 的访问者使用站点额度 | 每 IP 5 次问诊/天，全站 200 次问诊/天 |
| **用量看板** | `/api/usage` + 前端显示剩余次数 | 80% 预警，100% 降级 |

**四条硬要求**：
1. **请求前拦截**——被拦的请求不产生费用
2. **按 `llm_calls` 计量，不按请求数**
3. **超限降级到回放而不是报错**——访问者仍能看到录制主诉的完整结果
4. **不做通用代理**——访问者的 key 只用于本次问诊

实现要点：`TRUSTED_PROXY_HOPS` 默认 0，即不读 `X-Forwarded-For`（直接信任 XFF 等于让任何人换
一个请求头就换一个"IP"），只有部署在自己的反向代理之后才设为代理层数；额度变量为
`QUOTA_PER_IP_DAILY_CALLS`、`QUOTA_GLOBAL_DAILY_CALLS`、`QUOTA_MAX_TRACKED_IPS`，单位是调用数；
问诊开始前按"这次至少会花几次调用"预扣，结束后按真实调用数结算；`FORCE_REPLAY=1` 强制全站走
回放。部署步骤见 `docs/DEPLOYMENT.md`。

### 前端的 BYOK 入口

放在顶栏右侧，默认收起为一行小字「用自己的 API key（不限次数）」。点开是一个输入框 + 一句说明：

> 你的 key 只在本次请求中转发给 DeepSeek，不会存储在服务器上。
> 关闭标签页后即清除。

不做成弹窗，不在首次进入时拦路。

## 5.2 三种后端

| 后端 | 用途 | 特点 |
|---|---|---|
| `api` | 开发、评测、在线使用 | 实时调用 OpenAI 兼容接口 |
| `local` / `local_inproc` | 本地部署 | vLLM，guided decoding 从解码层保证 schema，LoRA 按医家切换 |
| `replay` | 离线展示 | 零成本、可断网、每次结果一致 |

**回放模式的定位**：适合预设主诉的展示，**不适合让别人自由输入**（按主诉原文的哈希索引，差一个
字就未命中）。

**前端必须显示回放模式提示**，挂在顶层 `replay_mode` 字段——非研究者角色的 manifest 会被整个
裁掉，而回放结果同样会展示给患者、医生、学生角色。提示样式：顶栏下方一行小字，琥珀色
（`--caution-bg` 底、`--caution` 字），醒目但不用朱砂警告色（它不是错误）：

> 回放模式：结果来自 〈录制日期〉 录制的真实推理（〈模型名〉），非实时调用

# 第七部分 · 不可妥协的设计约束

这七条是这个产品的骨架，任何改动不得违反：

1. **三家平等**。没有哪一家是"正确答案"，界面上不得出现主次、排名、推荐。
2. **分歧必须带 ε**。任何展示医家差异的地方，都要同时给出当前主诉的噪声地板。
   没有 ε 的差异数字是误导。
3. **患者模式不出方药**。这是安全边界，从数据构造层就断掉，不是前端隐藏。
4. **危重拦截整页替换**。不是加个横幅——什么都标红等于什么都没标。
5. **每条结论可追溯**。证型、治法、方药都要能点开看引了哪条医案原文。
6. **回放模式必须自报**。回放的结果不得伪装成实时调用。
7. **色只承担语义**。带颜色 = 属于某位医家，或者在报警。不做装饰性配色。

# 第八部分 · 参考医家（§8）

注册表 `core/physicians.py` 中登记了五位医家；李可、王云启两位是**参考医家**：注册但不参与三列
集注。三列集注如果变成五列，会破坏第七部分第 1 条赖以成立的版面。

## 注册但不参与集注

```python
"li_ke":      {..., "enabled": False, ...}
"wang_yunqi": {..., "enabled": False, ...}
```

`enabled` 回答的是**"要不要在三列集注里占一列"**，不是"这位医家的数据要不要用"。
另一个字段 `in_synthesis` 回答"是否参与综合分析"（结构化模式只输出一份融合结论）。

| 场景 | `enabled=False` 的医家是否参与 |
|---|---|
| 三列集注（问诊页主区） | **不参与** |
| 检索语料 | 参与（需要自行获取其语料，见 `data/SOURCES.md`） |
| 图谱医案层 | 参与 |
| 学生 / 研究者模式的「参考医家」引用区 | 参与，**不占列**，折叠在三列之下 |
| ε / E3 / E4 / E8 / E9 / SDT 评测 | 不参与（换了医家集合的数字与已有结果不可比） |

## 两个入口，禁止别处自己过滤

```python
physicians_enabled()   # 参与集注的（三位）
physicians_all()       # 注册表全部（五位）
physicians_for_mode(mode)  # 按 S3_MODE 选名单的唯一分派点
```

不在任何地方手写 `{k: v for k, v in PHYSICIANS.items() if v["enabled"]}`：过滤条件一旦变化，
散在各处的推导式不会跟着变（`docs/ARCHITECTURE.md` §4）。

## 界面上的「参考医家」形态

折叠区，标题「参考医家（不参与三家对照）」，每位医家列出最相关的几条医案引用，带身份色的一条
左边框。**含十八反配伍的医案必须带那句固定提示**（常量定义在 `core/safety_output.py`，训练语料与
界面共用同一句）——名家的用药有其学术依据，但本系统的安全层按药典拦截，两件事都要说清。

# 第九部分 · 性能预算（§9）

没有预算的"优化"无法验收。每一条都有对应的测量脚本，数字由脚本产出：

| # | 项目 | 预算 | 怎么量 |
|---|---|---|---|
| 1 | 热启动（第二次起进程） | ≤ 20 s | `python -m scripts.bench_startup`（运行两次进程，看第二次） |
| 2 | 一次问诊，不开 ReAct | ≤ 90 s | `python -m scripts.bench_consult --backend real --repeat 3 --no-react` |
| 3 | 一次问诊，开 ReAct | ≤ 240 s | `python -m scripts.bench_consult --backend real --repeat 1 --react` |
| 4 | 图谱浏览器首屏 | ≤ 1 s | 浏览器 Performance 面板 / Playwright 计时 |

**预算的三个前提**（不写清楚，数字就无法复现）：

1. **模型**：默认 `deepseek-v4-pro`。换模型，这几个数都要重新测量。
2. **思考设置**：S1/S2/追问/ReAct 关闭思考，S3 按 `S3_THINKING`（默认开启）。关闭 S3 的思考会明显
   更快，但那是另一组数——`manifest.thinking_by_step` 记录了实际设置，两组数不能混用。
3. **并发**：问诊内部多位医家并发推理，进程级同时在途的 LLM 调用数由 `LLM_MAX_INFLIGHT`（默认 6）
   封顶；它与 `MAX_CONCURRENT_CONSULTS`（同时进行的问诊数）是两道独立的闸。

**预算不达标时**：如实报出实测值和差距，不调 `--repeat` 或换一条更短的主诉把数字凑进预算。
预算是用来暴露问题的。
